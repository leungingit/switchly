# MR-D12：上一首与近期封面复用（2026-11-10）

## 问题与实施

正常启动已使用组合桥，但此前 Session 仅保留当前图片，A → B → A 需要重新接收并解码封面；切歌屏障只接受不同歌曲，不能识别 previous 引起的同曲重播。

按 [MR-D12](../../plugins/mediaremote/music-mediaremote-integration-plan.md) 实施：

- `MediaArtworkHistory` 独立负责 LRU、歌曲键和实际位图内存计费；最多 8 张、8 MiB，不持有历史进度、喜欢或播放状态。
- `MediaRemoteSession` 负责会话范围和复用时机；完整原生身份与元数据匹配后可在图片字节缺席时恢复历史图；再次收到相同字节也复用解码结果。新字节优先，显式清图、无效数据和解码失败撤销缓存。不能识别清图所属歌曲时保守清空历史。
- 原生 ID 和元数据精确匹配，时长沿用原有配对的 1 秒容差。真实流媒体事件出现 `300 → 300.073 → 300.029` 的时长精度修正，不应导致缓存失配。
- `MediaRemoteState` 仅处理 previous 的明确同曲进度回退：先前大于 2 秒，新事件明确报告 0～2 秒且至少回退 1 秒；重建进度锚点与图片代际。next、普通进度与迟到图片不能解除屏障。
- `CompositeMediaBridge` 仅传入命令语义，仍执行原有 AppleScript 双采样配对与整组回退。公开 API、插件代码、默认桥选择、控制／喜欢／资料库能力不变。

模块依赖仍为装配 → 组合桥 → Session／状态机／独立缓存；Views 与插件不参与来源选择和历史缓存。复用结果使用当前歌曲代际的图片 token，旧展示上下文不会因此重新获得有效资格。

缓存只在可见读取会话内有效。浏览器抢占、连接变化、目标进程变化、睡眠或最后读取兴趣撤销清空历史；隐藏后再次悬停不承诺缓存命中。仍只有一个在途解码与一个最新候选。
