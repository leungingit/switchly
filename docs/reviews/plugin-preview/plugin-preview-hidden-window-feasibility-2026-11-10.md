# 隐藏原生窗口的后台视觉闭环与可行性裁决

日期：2026-11-10。接续[第六轮](plugin-preview-renderer-color-lifecycle-2026-11-10.md)。用户要求继续验证，并给出能否实现后台视觉验证、不影响用户前台使用的确切结论。仍只做临时实验，不接入正式工具。

实测环境：arm64、macOS 27.2（26B123）、Xcode 27.2（27B52）、已有捕获授权的本机 GUI 会话。采用当前共享 Renderer、真实外仓 iPod GLB 和合成媒体 fixture，不操作真实 Music。

**裁决：本机的核心目标可实现。** 已在从创建起就不排序到屏幕的原生窗口中，取得有效截图、2D 原生控件动作、3D 点击和拖动及动画更新，同时保留用户前台。普通 2D 对照像素一致；3D 玻璃区域仍有最大 7/255 的通道差，完整逐像素等价未通过。正式工具尚未接入，旧系统、跨 Space、全部输入形式和资源压力未验，不能宣布全平台交付完成。

## BG-D26：透明、完全离屏与隐藏是三个不同变量

独立 AppKit／SceneKit 校准包含棋盘、可变色块、原生 SCNView 方块，以及 `.hudWindow/.withinWindow/.active` 的 NSVisualEffectView。窗口为 `.nonactivatingPanel`，不可成为 key／main、鼠标穿透、无阴影，位于桌面层级以下。只捕获探针自己的窗口，不截取用户桌面或其他应用。

对照三条系统捕获路径：

- `/usr/sbin/screencapture -x -o -l <windowNumber>`。
- ScreenCaptureKit 的 desktop-independent 单窗口 `captureImage`，显式设置 `ignoreGlobalClipSingleWindow=true`。
- macOS 26+ 的 `captureScreenshot`，显式设置 `ignoreClipping=true`。

关键结果：

| 窗口状态 | 原生命令 | SCK 两条路径 | 内容核验 |
| --- | --- | --- | --- |
| 屏幕内、alpha=1 | 返回图像 | 返回图像 | 控制样本有效 |
| 屏幕内、alpha=0.01 | 返回图像 | 返回图像 | 原生图平均 alpha=3，不能作为保真画面 |
| 屏幕内、alpha=0 | 退出 0、返回图像 | 返回图像 | 三者均完全透明，平均 alpha=0，不能算捕获成功 |
| 与所有显示器不相交、alpha=1 | 退出 1 | 均为 -3811 | 忽略裁剪配置没有修复完全离屏捕获 |
| orderOut、alpha=1 | 返回图像 | 返回图像 | 可取得内容，需排除旧帧与初始化时序 |

隐藏后连续改变四个色块和四个 SceneKit 位置／角度，再分别取得同状态可见参考，确认内容能够更新。初始 warm／透明初始化样本的 24 个隐藏／参考比较（两种初始化×四状态×三捕获方法）RGB 差为 0。完全不排序、显式 sRGB、显式显示器颜色空间、先完全离屏预热等校准也能取得新内容，但原生玻璃有约 1.09 MAE、最大 8～9 的残差。它们没有被写成逐像素完全一致。

公开 SDK 没有“忽略全局窗口 alpha”或“保证隐藏窗口可捕获”的配置。`ignoreGlobalClipSingleWindow` 的说明只覆盖部分离屏裁剪。本机正向结果属于真实运行证据，不能外推为所有系统的 API 保证。相关公开定义见 [SCWindow](https://developer.apple.com/documentation/screencapturekit/scwindow)、[ignoreGlobalClipSingleWindow](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/ignoreglobalclipsinglewindow)；本轮也直接核对本机 SDK 头文件。

## BG-D27：否决透明切换初始化，采用从不排序的窗口

真实共享 Renderer 首先尝试 `alpha=0 → orderBack → orderOut → alpha=1`。紧邻调用时，曾取得完整画面和动作；但一个运行的隐藏阶段，外部观察仍记录到一次上屏窗口数为 1。随后在 orderOut 后加入 80ms 等待和窗口列表确认，再恢复 alpha=1，五个独立进程虽然动作回调正常，隐藏截图却全部透明。

中间进度曾依据动作回调把重复运行判断为通过，像素核对后已更正。**这批运行不计入最终正向闭环。** 该初始化对提交时序敏感，本轮否决它作为候选方案；未确定 WindowServer 内部的唯一成因。

最终七个采用样本使用以下组合：

1. 创建 accessory 预览进程，不创建工作台。
2. 创建 `.borderless/.nonactivatingPanel` 的 NSPanel，`canBecomeKey=false`、`canBecomeMain=false`、`ignoresMouseEvents=true`、无阴影；外观显式匹配场景。
3. 窗口几何 frame 保持在真实显示器内，保留显示环境；从创建到后台验证结束，**从不调用 orderBack／orderFront／makeKey**，保持 alpha=1。
4. 挂载原 NSHostingView 和共享 Renderer，处理布局、`displayIfNeeded` 与场景事务，直接按 windowNumber 取得单张原生截图。
5. 初始化时确认窗口不在 CG 上屏列表；每次后台捕获都检查 `isVisible=false`、`isKeyWindow=false`、应用未激活。

这是“窗口有原生呈现表面，但没有排序到用户屏幕”的路线。它与完全移出屏幕不同，也不再使用 cacheDisplay、SCNView.snapshot 或临时 NSImageView 替换来合成图片。

为取得保真参考，实验在**全部后台操作与隐藏截图结束后**，才将同一个窗口 orderBack 到桌面层级以下并捕获同状态参考。这个参考阶段明确排除在后台可见性统计之外；正式后台候选路径不需要这一步。本轮没有修改正式工具。

## BG-D28：隐藏窗口需要按实际原生组件分派输入

按截图重新取点并核对真实 `wheel_ring` 几何后，隐藏窗口的 `NSWindow.sendEvent` 仍没有触发动作。临时关闭 `ignoresMouseEvents` 也没有恢复，不能把这个开关当成修复。直接调用 NSHostingView 的 mouseDown 在本例同样没有触发 SwiftUI 按钮。

最终有效的两个通道：

| 内容 | 通道 | 最终采用结果 |
| --- | --- | --- |
| 2D SwiftUI 控件 | 外部公共 AX 只读访问初始化应用 AX，再调用原 `PluginPreviewNativeDriver.press` | 三个独立进程均为 Go pressed → Stop disabled → Mute pressed；缺失标签为 notFound |
| 原生 SceneKit 视图 | 根据窗口局部坐标 hitTest 到真实 `PluginScene3DPointerView`，将 NSEvent 交给该视图的原 mouseDown／mouseUp／mouseDragged | 四个独立进程共 16 次 toggle、4 次 love、4 次原生拖动，均取得动作或相机状态及图像更新 |

2D 每轮均核对 `last:none → last:go → 禁用 Stop 后仍 last:go → last:mute`，缺失标签动作增量为 0。原生按压经共享控件回调、现有 session、worker 和 render 更新，不直接调用 JS 业务 action。

3D toggle 的视口 top-left 坐标为 `(150,389)`，love 为 `(150,276)`；按 SCNView 实际 frame 换算窗口坐标。每轮四次 toggle 的 UI 树均依次为 `play.fill=2/pause.fill=0` 与 `play.fill=0/pause.fill=2` 交替。love 经真实鼠标回调更新合成媒体状态，并显示产品已有的 SwiftUI 爱心。拖动通过原视图的三个鼠标处理方法，四轮均从零姿态改变 yaw 超过 30°、pitch 超过 15°。

这些是目标进程内的原生输入路径，**不是 WindowServer 全局鼠标输入**，也不是直接业务 action。没有移动系统指针、没有向全局 event tap 注入键鼠；2D 与 3D 的通道尚未实现为统一正式工具协议。已知坐标和几何核验不等于证明 Agent 已能自主定位任意 UI。

## BG-D29：七个进程、83 张有效后台截图及保真边界

最终采用 2D 三轮、普通 3D 三轮、额外几何／遮挡 3D 一轮，共七个独立进程。2D 每轮五张后台图，3D 每轮十七张，共 **83 张后台原生图**，另有七张参考。逐张解码验证：所有后台图平均 alpha=255，均非单色图，排除了透明图片、空白图片和仅凭退出码判定成功。

所有图统一转换为 8-bit sRGB RGB 比较，2D 720×230px、3D 600×1032px。差异像素仍沿用某一 RGB 通道绝对差 >8 的描述口径，**该口径不是验收容差**；像素完全相同另以 max=0 判定。

| 最终采用组 | 隐藏末图对同状态原生参考 MAE | 最大通道差 | 差异像素 >8 | 玻璃区域外最大差 |
| --- | ---: | ---: | ---: | ---: |
| 2D 第 1～3 轮 | 0 | 0 | 0 | 不适用 |
| 3D 第 1 轮 | 0.458231 | 7 | 0 | 0 |
| 3D 第 2 轮 | 0.457734 | 7 | 0 | 0 |
| 3D 第 3 轮 | 0.457639 | 7 | 0 | 0 |
| 3D 裁剪／遮挡轮 | 0.458231 | 7 | 0 | 0 |

3D 残差全部位于实验原生玻璃的包围矩形，图像坐标 `x=80..<520、y=452..<652`；区域外 RGB 绝对差总和为 0。原生玻璃保留了实际模糊、颜色和遮挡；主控已实际看图。它显著不同于前几轮缓存路线丢失背景模糊，但**仍不是逐像素完全相同**，也未定位这 7/255 差值的唯一原因。

几何／遮挡轮额外使用 root 的原生 CAShapeLayer mask：矩形 `(40,55,220,390)`、圆角 70pt，实际裁掉 iPod 上下与侧边；加入 `(50,80,200,80)`、alpha=0.55 的青色前景，并保留原生玻璃。主控实际查看点击后与拖动后的图像：裁剪随原树生效、前景保留、3D 与玻璃同图存在。与可见参考比较，几何、半透明及区域外像素一致，残差仍只在玻璃区域。

此前分层缓存路线的玻璃失败和裁剪失败数据继续有效；本轮通过的是另一条原生窗口路线，不是声称修好了旧缓存实现。

## BG-D30：动画来自一个原生返回图，确定性时间回放仍未证明

四个 3D 采用进程均在后台捕获到真实爱心出现和消失，并取得旋转、原生拖动的画面变化。沿用第四轮的固定粉色 ROI 与判定方式：`x=230..<370、y=330..<490`，R>130、R>G+55、R>B+35。

| 采用组 | 点击前 | 四次 love 捕获的粉色像素 |
| --- | ---: | --- |
| 普通 3D 第 1 轮 | 0 | 1869、2487、0、0 |
| 普通 3D 第 2 轮 | 0 | 2090、2487、0、0 |
| 普通 3D 第 3 轮 | 0 | 1913、2487、0、0 |
| 几何／遮挡轮 | 0 | 1842、2488、0、0 |

相位之间实际异步等待 80／140／220／300ms，且包含原生截图耗时；不当成精确帧时间。主控看过爱心、模型和玻璃同图的真实截图，以及裁剪后的拖动画面。普通三轮 spin 首末图差异像素约 41.26%、38.07%、44.14%，几何轮约 22.06%，确认画面持续更新。

spin 使用现有 controller 作为独立动画刺激，不计为原生输入；原生拖动另有真实事件和状态证据。每张最终图只由一次原生窗口捕获返回，工具不再先后抓取 2D 和 3D 再拼接，因而移除了工具自身的跨调用分层时间缝隙。

**没有证明** SwiftUI、SceneKit 和 Timer 能以指定绝对时间确定性回放，也没有取得证明所有内部 GPU 时间源原子一致的时间戳。BG-D23 的反例仍成立。应将“单张原生窗口视觉结果”与“任意动画时刻的逐像素确定性回放”分别表述。现有契约本来也只允许固定时钟且关闭玻璃的运行接受视觉基线，见[预览契约 §6](../../plugins/preview/plugin-preview-contract.md#6-视觉基线)，本轮没有更改该门禁。

## BG-D31：后台阶段可见性、激活与输入隔离证据

最终六个普通采用进程和额外几何进程均由独立观察进程从启动前监测到退出后。后台阶段定义为创建后的 hidden-ready 至 hidden-final 捕获完成；可见参考阶段排除。

- 7 个进程后台阶段的内部记录均为 `visible=false、key=false、active=false`。
- 6 个普通进程共 759 个外部心跳，几何进程另有 185 个；最大间隔分别为 54.915／52.481ms。全生命周期均未观察到目标进程激活。
- 其中后台区间共有 **803 个外部样本**，目标进程的上屏窗口数全部为 0；初始化另有未排序窗口的 CG 列表检查。
- 七个进程各自的前台 PID 采样保持一致。六个普通进程各自的指针采样位置保持一致；几何进程记录 12 个位置，未采集来源，不据此声称所有轮次指针均不变。
- 正向输入代码只访问自有 AX／原生视图响应者，没有全局鼠标投递、指针移动或键盘监听。业务使用合成 fixture，不改变用户真实媒体状态。

本轮“不占用用户前台”的可行性结论，具体指后台候选不显示到桌面、不夺取前台和 key、不借用全局键鼠输入。没有做用户连续打字吞吐、CPU／GPU 压力、所有 Space／系统界面和全系统版本测试，不扩大为零资源消耗或任意系统行为的保证。第五轮的历史激活事件仍保留，来源没有被本轮倒推解决；最终路线有新的结构约束和本机独立证据。

## BG-D32：明确裁决与正式接入边界

| 判断对象 | 裁决 | 依据 |
| --- | --- | --- |
| 本机后台看图、2D／3D 点击和 3D 拖动，不占用用户前台 | **可实现，本机可行性通过** | 七个进程、83 张有效后台图、真实动作／状态／图像更新、803 个后台外部样本上屏数为 0 |
| 从完全屏幕外窗口按现有系统捕获 API 取得图像 | **本轮仍失败** | 原生命令失败，SCK 忽略裁剪配置仍返回 -3811 |
| 透明切换初始化作为稳定后台方案 | **否决** | 插入隐藏确认等待后，动作成功但图像全透明；旧顺序还有一次上屏记录 |
| 原生玻璃与前台逐像素完全一致 | **未通过** | 最终路线残差局限于玻璃，最大通道差 7、MAE 约 0.458 |
| 任意动画时刻的跨时钟确定性回放 | **未证明** | 本轮使用单张原生图，不控制全部内部时间源 |
| 当前正式工具已经具备后台原生输入 | **否** | 本轮未接入，`run --background` 的 nativeClick 仍为 unsupported |
| macOS 12、Intel、其他系统和全部输入的产品发布 | **不放行** | 未完成对应系统与输入矩阵 |

后续工程方向确定为**优先验证并接入不排序的原生窗口表面及目标进程内输入适配**，不继续把分层拼图作为主路线。正式接入前必须写清能力边界、捕获语义、错误出口和兼容性自检；隐藏捕获不可用时返回明确的 unsupported／environment error，不能回退为抢前台或显示窗口。3D 坐标适配与 2D AX 路径仍需正式协议及回归，不把本轮硬编码坐标当成通用工具实现。

只读 runner 清单未发现已验证可立即使用的运行中 macOS GUI runner；没有启动、安装或创建 VM。独立 GUI 环境仍可作为更广泛系统级输入的备选，本轮已经不需要用“必须先有 VM”解释上述本机插件闭环。

PV-T02／PV-T03 的正式集成与发布门禁保持未放行。本机可行性通过和正式能力未接入是两个独立状态。

## BG-D33：实际验证与卫生

临时探针、候选、AX 只读 helper、观察器和像素程序实际编译并运行。开发中出现过 SCNVector3 标量类型、Swift 运算符空白的临时编译错误，均修正后才运行；未修改仓库 Swift。候选与探针退出 0 仅作为运行记录，采用证据另检查原始 JSON、回调、图像内容、alpha、参考像素与外部监测。

最终一致性检查真实输出：

```text
PASS accepted_processes=7 hidden_png=83 valid_alpha=83 nonuniform=83 toggle=16 love=4 drag=4 2d_sequences=3
共享源码守卫通过：33 个核心类型各一处定义，预览 target 编译宿主源码
```

主控实际看过透明失败图、隐藏校准矩阵、2D mute、3D 播放切换／爱心／旋转，以及裁剪／半透明／拖动图。报告链接、证据一致性和 `git diff --check` 通过。仓库仅增加本报告、台账及索引，没有正式 Swift 修改，因此未运行宿主全量 build／unit。候选、PNG、JSON、helper 和日志均在系统临时目录，核验后清理。未使用 Skills、重启正式 Switchly、启动真实媒体、提交或推送；保留用户已有工作区修改。
