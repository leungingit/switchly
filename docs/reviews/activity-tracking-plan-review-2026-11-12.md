## 1. 评审结论与边界

方向合理，建议保留 AT-D01 的宿主采集与插件展示分工、AT-D02 的两级默认关闭，以及不向插件提供截图像素或路径的边界。当前方案足以讨论产品目标，但不足以直接进入实现：计时口径、隐私范围、数据生命周期及独立面板协议仍缺少可验证合同。

建议先交付“无截图的应用时长最小闭环”，以独立插件面板展示当日排行和区间；完整日期控件、长期历史与截图采样分别设门槛，AI 不进入本轮。宿主保留通用服务与面板容器，插件展示代码仍唯一维护在相邻 `switchly-plugins`，不新增宿主按插件 ID 的业务分支。

本记录的 `AT-Rxx` 是问题编号，`AT-RDxx` 是评审建议编号，均不自动替代原 AT-D01～D07，也不代表用户批准。原 T0.1 的用户确认仍待完成；本轮不提前修改已发布隐私承诺、机器可读 API 或运行代码。

## 3. 建议先冻结的合同

### AT-RD01 计时对象是应用前台停留，不推断工作效率

- 同一时刻最多一段可计时区间；同应用多窗口不拆应用时长。全屏或跨 Space 时以确认的前台应用为准，不为采集主动切 Space。
- `disabled`、`tracking`、`idle`、`locked`、`sleeping`、`inactiveSession` 的转换要明确；排除应用、无 bundle ID、Finder/桌面及 Switchly 自身的处理在 T0 固定。多个阻断原因叠加时，必须全部解除才恢复。
- 开启时读取当前前台；重复激活不重复开段；关设置、目标退出、退出 Switchly、锁屏、睡眠、会话失活均结段。恢复只从实际恢复时刻开始，不把中断期补成活跃。
- 建议采用“无输入达到 5 分钟后，将最后输入之后的区间回退为空闲”的口径；这会排除无输入阅读/视频观看，需在 UI 明示。检查点与查询须支持这段未决时间的修正，不能只改内存而保留已写入的活跃时长。该建议待用户确认，不能只写“阈值 5 分钟”。
- 区间为 `[start, end)`；运行态与已结束区间分离，持久化带 schemaVersion、检查点及结束原因。明确崩溃后最多损失一个检查点周期，不跨重启补记。
- 建议首版按查询选择的单一时区重新分桶，所有日期 UI 与查询显式使用该时区；跨午夜按桶裁剪，夏令时一天允许非 24 小时。原始记录不因切换查询时区被重复物理拆分。系统时钟跳变需分段并保留异常标记。

Apple 的 [secondsSinceLastEventType](https://developer.apple.com/documentation/coregraphics/cgeventsource/secondssincelasteventtype(_:eventtype:)) 返回距上一输入事件的秒数，适合作为空闲信号，不足以证明用户没有阅读；[sessionDidResignActiveNotification](https://developer.apple.com/documentation/appkit/nsworkspace/sessiondidresignactivenotification) 描述用户会话切出，[willSleepNotification](https://developer.apple.com/documentation/appkit/nsworkspace/willsleepnotification) 描述睡眠前通知，二者均要求向 NSWorkspace 的通知中心注册。它们不能替代尚未实测的锁屏闭环。

### AT-RD02 时长数据与截图采用独立生命周期

T0 必须给出一张最终保留表：记录种类、默认天数、硬上限、过期检查时机、清除对象与权限。原 AT-D04 的 7 天/256 MB 可以保留为截图候选值，不能套用于所有数据或反向假设时长永不删除。

活动目录/文件采用仅当前用户访问的权限（0700/0600），明确是否加密；日志不输出应用名、窗口标题、截图路径或完整区间。截图合同还需固定最大边长/像素数、单图字节和解码预算，不能只用总容量定义“小图”。

年视图只有两条明确路径：保留足够久的日聚合，并向用户说明更早的明细/截图已过期；或首版只支持保留期内的查询。需要用户决定，不能显示空白后暗示该年未使用。最小闭环先只展示当日，不阻塞验证采集准确性。

存储选型应在纯接口与数据量夹具验证后尽早固定：单日分片 JSON 可作为最小闭环候选，若同时承诺长历史、多维查询、分页和摘要/截图关联删除，应优先验证系统 SQLite。不并行保留两套生产后端，也不机械地对数据库“整个文件原子替换”。损坏备份也受保留和清除约束；更高 schema 版本不能被静默覆盖。

### AT-RD03 权限分层，插件不控制采集

区分宿主记录开关、宿主截图开关、系统屏幕录制权限、插件读取授权。插件打开面板不自动开启记录；关闭插件不隐式删除用户历史，关闭采集是否保留历史需明确提示。

建议 `activity.read` 只覆盖约定的应用时长/区间，截图展示使用独立授权候选 `activity.snapshots`；最终名称待合同评审。读取授权不等于采集授权，既有 `window.capture` 的一次用户主动截图许可也不等于后台留存许可。撤权、清除、保留期变化都要使结果和图片引用失效。

### AT-RD04 最小插件面板先于通用日期控件和截图网格

保留“独立插件面板”目标，但先完成通用 panel 生命周期，不一次实现完整控件库。首版展示当日/上午/下午、前后一天（限制在已保留范围）、应用排行和分页区间；短列表复用现有节点。宿主仍提供统一设置、授权和清除入口。

面板合同必须解决：仅 panel 插件如何声明 matches、菜单入口如何按插件身份装载、`ctx.app/window` 缺席或不同含义如何兼容、是否共享 VM、按 surface/实例区分的展示状态、面板输出类型、动作载荷和目标绑定。复用可见性租约，验证关闭任一 surface 不暂停另一可见 surface。

`apiVersion: 3` 仅是原方案候选。当前宿主与 schema 只接受 1/2；应先判断新增 surface 是否需要新的主合同，纯可选查询是否可走能力协商。若采用 v3，SDK、CLI、验证器、预览、宿主拒绝旧版本行为与 1/2 回归一起修改，不先在生产清单声明未实现能力。
