# 窗口截图与标注插件：方案与任务划分

> 状态：首期实现与当前机器自有窗口验收完成，平台集成待验（2026-11-11）。用户授权先验证、可行后继续实现；以下 WC-D08～D13 为本轮验证后的有效合同，覆盖旧草案对应条款。实施与验收状态见第 6 节。

## 1. 目标与非目标

**目标**

1. 在 Dock 预览的每张窗口卡片上提供相机按钮，点击后展开「快速」「自定义」两个选项。
2. 快速：直接截取该窗口的完整原始分辨率图像。
3. 自定义：先抓取目标完整窗口，在冻结图像中选择区域并裁剪，不聚焦其他应用。
4. 截图可复制、保存或分享；需要标注时交给系统「预览」，保存关闭后显式重读，再输出。
5. 尽量复用系统能力，降低实现成本。

**非目标（首期）**

- 不自研完整图像编辑器，不引入第三方编辑库。
- 不做滚动长截图、录屏、OCR、云端上传或截图历史库。
- 插件 JS 不持有图片像素或文件路径。

## 2. 初审差距与最终处理

| 需求 | 现有能力 | 差距 |
| --- | --- | --- |
| 卡片上的按钮与展开选项 | 原实现按应用绑定第一扇窗口 | 新增 renderScope、每卡片挂载和 labeled 文字按钮 |
| 完整窗口截图 | `ThumbnailService` 以 CG 为主、macOS 14+ SCK 为兜底，产出缩略图 | 插件不可调用；需原始分辨率输出 |
| 拉起窗口 | Accessibility 聚焦与最小化恢复已存在 | 新流程不聚焦外部窗口；最小化、隐藏目标明确失败 |
| 冻结图像选区 | 插件无自由绘制 | 宿主截图窗口在同一位图上拖选裁剪 |
| 编辑 | 无 | 交由「预览」，保存关闭后显式重读 |
| 输出 | 插件无文件写入、无剪贴板 | 宿主提供复制 / 保存 / 分享 |

## 3. 关键决策

- **WC-D01 插件只做入口，宿主做截图与编辑**：插件负责按钮、展开与调用；截图、冻结选区、编辑交接、输出由宿主 Service / AppKit 层持有。原始像素与系统窗口都超出插件运行时边界。
- **WC-D02 新权限 `window.capture`（被 WC-D09 取代）**：用户确认后才注入 `ctx.capture`；插件只收到结果状态（`saved` / `copied` / `cancelled` / `failed` + 原因码），不收到图像或路径。
- **WC-D03 复用截图管线（被 WC-D13 细化）**：原草案要求复用缩略图抓取；正式实现将 CG / SCK 底层提取为共享服务，原图不写入 `ThumbnailDiskCache`。
- **WC-D04 自定义选区由宿主遮罩实现（被 WC-D10 取代）**：旧方案在真实窗口上选区后再次截图。
- **WC-D05 编辑首选系统标记（被 WC-D11 取代）**：旧方案假定 Quick Look 可直接进入标注；未获得支持这一闭环的公开接口证据。
- **WC-D06 输出与清理（被 WC-D12 取代）**：旧方案未定义外部编辑器的完成信号。
- **WC-D07 隐私变更文档先行**：原始分辨率截图属于用户主动触发的新本地处理能力，需先更新 `PRIVACY_POLICY.md` 与 `AGENTS.md` 第 6 节，再合并实现。

### 2026-11-11 验证后合同

- **WC-D08 按窗口渲染**：新增可选 `renderScope: "app" | "window"`，默认 app；window 插件按卡片渲染，拥有该卡片不可替换的目标上下文。旧插件继续只在应用叠层运行。卡片挂载 titleAccessory / topTrailing / bottomBar，不能简单复制第一扇窗口的 UI。
- **WC-D09 短调用、长会话**：`ctx.capture.window({ mode: "full" | "region" })` 仅在获准插件的真实 onAction 调用期间可提交一次，目标由宿主上下文绑定，拒绝额外 windowID。立即返回 `Promise<{status:"accepted"}|{status:"failed",reason}>`；accepted 不是已保存。宿主持有独立会话，收起 Dock 不取消已接受任务。撤权、卸载及退出时取消；插件无像素、路径、最终输出位置。预览注入模拟提交器，绝不真实截图。
- **WC-D10 冻结图像选区**：先新鲜抓取目标完整窗口，再在宿主截图窗口显示同一冻结位图；拖选矩形、回车确认、Esc 取消，按图片显示矩形换算到真实像素后裁剪。不再要求把其他应用聚焦或切换 Space；避免选区后重截引入画面变化。最小化和无法读取的窗口返回明确失败，不使用旧缩略图替代。
- **WC-D11 系统编辑显式交接**：当前环境 Quick Look 无标注入口。首期使用「预览」标注：用户点击“在预览中编辑”，保存并关闭该图片后返回宿主，点击“读取已保存的修改”；宿主重新解码文件才更新输出。打开回调仅代表成功打开，不视为编辑完成。不自研标注工具、不使用私有 API 或自动化脚本控制编辑器。
- **WC-D12 文件与输出**：普通截图和裁剪只驻内存；仅在用户点击外部编辑时写入 0700 的会话临时目录、0600 PNG。打开编辑器后，在用户确认保存关闭并读取前，禁止输出与自动删除该文件。取消编辑时明确要求关闭外部图片后再结束。分享使用内存图片并由系统用户主动选择；打开分享菜单不等于分享成功。保存通过 NSSavePanel 显式选位置，不新增持久化设置。正常结束清理本会话文件，启动清理过期残留且不触碰其他运行实例的会话。
- **WC-D13 抓取复用与边界**：共享 CG / SCK 抓取底层，缩略图继续使用既有缩放和缓存策略；原图不经过缩略图缓存或 native 像素上限。SCK 原图尺寸使用 contentRect / pointPixelScale。超时使用一次性结果交付，超时不释放仍在执行的底层工作名额，底层并发有界。身份按宿主绑定的 PID、进程启动时间、windowID 复核；禁止退化为整屏或其他窗口。原图超过明确像素预算时失败，不静默降采样。

验证记录见 [窗口截图可行性验证（2026-11-11）](../reviews/window-capture-validation-2026-11-11.md)。旧第 4、5 节流程和 API 草案由以上条款取代；任务验收按新合同执行。

## 4. 当前交互流程

```text
每张卡片 titleAccessory: 相机
  点击 → 当前卡片 topTrailing 展开“快速截图 / 自定义选区”

快速：
  用户动作 → 短提交 accepted → 宿主接管并收起 Dock → 新鲜原始窗口位图 → 截图窗口

自定义：
  同上 → 冻结位图选择矩形 → 回车或按钮确认裁剪 → 截图窗口

标注（用户可选）：
  在预览中编辑 → 私有临时 PNG → 系统预览标注
  → 用户保存并关闭该图片 → 返回宿主显式读取修改 → 解码更新图片

输出：
  复制 / NSSavePanel 选择位置保存 / 系统分享选择服务
```

不再用“隐藏预览面板”代替目标窗口过滤；共享抓取底层始终只截指定 windowID。没有屏幕录制权限时入口不可用并有授权提示；无 AX 不会阻止冻结图像选区。最小化、隐藏或身份失效的目标失败，不用缓存冒充原图。PNG 上限 40,000,000 像素、文件上限 128 MiB，超限明确失败，不静默降采样。

## 5. 当前插件 API

- manifest：`renderScope: "window"`、`permissions: ["window.capture"]`；可用 `matches: ["*"]` 匹配所有应用。旧插件省略 renderScope 仍按应用渲染。
- `ctx.capture.window({ mode: "full" | "region" })` → `Promise<{status:"accepted"}|{status:"failed",reason}>`。
- 请求不接受 windowID/PID/路径；只在获准插件真实 onAction 有效调用期间可提交一次。实际目标绑定于宿主上下文，不能通过修改 ctx.window 替换。render、定时器和旧调用保存的接口均不能发起新流程。
- 提交失败原因：permissionDenied、noScreenPermission、noUserAction、invalidRequest、windowUnavailable、busy；抓取后的 windowGone、captureFailed、timeout、tooLarge 在宿主界面提示。accepted 不表示已输出；图片、路径和分享接收方不进入 JS。
- 同时只允许一个宿主会话。Dock 隐藏后继续，撤权或卸载中断输出；外部编辑中的文件保留至用户明确确认关闭，应用退出的残留按 24 小时清理策略处理，其他运行实例会话不清理。
- `ctx.presentationID` 标识一次叠层展示，插件可据此重置展开状态。button 新增通用 `variant: "labeled"`，显示文字且整行可点，旧 plain/prominent 样式不变。
- 预览 Worker 只模拟 accepted，不链接真实抓取、编辑和输出。
