## 1. 建议结论与成功标准

建议采用 **两个仓库、统一插件格式、同一运行协议、声明式扩展点、离线优先管理**：

1. `switchly`：宿主、通用系统能力、声明式渲染器、协议真源与 SDK 发布工具。保留可安装插件的能力，但不保留任何具体插件的源码、素材、业务规则或业务测试。
2. `switchly-plugins`（建议名，尚未创建）：所有现有官方插件及其业务测试、素材、说明、构建配置、目录索引。三个插件先全部迁入同一仓库；第三方可使用同协议在自己的仓库开发，不强制加入官方仓库。
3. “内置”改为产品分发概念“预装”：插件源码位于外部仓库，发布时将锁定的构建产物装入 App，用户首次启动不需要联网。
4. 官方、预装、用户安装、开发目录是不同维度。只有分发方式不同，调用协议与运行入口完全一致，官方插件也不能调用私有接口。
5. 第一期保留 JSC 与原生声明式 UI；先补契约、管理与生命周期，不直接迁移 Node/Bun，也不开放任意脚本或网络。

成功标准不能只看目录搬走：

- 插件仓库只有公开 SDK、合成夹具和宿主测试工具即可完成构建、业务测试及契约验证，不需要读取宿主源码。
- 宿主清空预装清单仍能构建和启动；新增使用已有能力的插件，只增加插件仓库内容及预装锁定清单，不改 Swift。
- 改插件算法、目标应用、素材、设置，不改宿主、不重新生成 Xcode 工程；用户本地安装新版即可使用，预装版本随下一次 App 发布更新。
- 宿主能够解释每个插件为什么未运行：关闭、待授权、不兼容、目标不匹配、槽位未选中、运行错误等。
- 1000 个已安装插件不等于 1000 个 VM；列出插件只读索引和 manifest，运行时按可见目标激活。

### 2.3 运行风险需单列，不能被“外置完成”掩盖

- **同步死循环不能被现有软超时停止。** `PluginRuntime.invoke` 的超时回调和 JS 执行在同一串行队列，同步阻塞时回调也无法运行；`unmount`、`onInvalidate` 的 `queue.sync` 还可能让调用线程等待该队列。此为静态代码推导，未执行恶意插件实验。独立 watchdog 能帮助诊断，但不能杀掉同进程 JS 执行。
- **隐藏不等于完全停机。** `DockPluginOverlayModel.stop()` 停止刷新并保留 VM，用于保留抽卡进度；Runtime 定时器随 VM 保留，不能沿用旧文档“关闭即卸载，因此后台零活动”的推断。
- **插件之间的 action ID 没有命名空间。** 合并时 `owners[actionID] = runtime`，两个插件用同一按钮 ID 会后写覆盖；应以 `(pluginID, instanceID, actionID)` 路由。
- **渲染调度按最短间隔串行执行所有匹配插件。** 某插件声明 1 秒会让其他慢频率插件一起运行；单插件缓慢也会拖延后续插件。应采用独立到期时间、有界并发和结果代次校验。
- **三项槽位限额只限制输出展示。** 当前没有在执行前截断所有匹配 Runtime；100 个匹配插件仍可能运行，再丢弃第 4 个之后的结果。
- **Host 锁内首次扫描和构造 Runtime。** `loadedPackages()` 可能读磁盘，不能据此宣称千级目录扫描不会卡住管理页。改为后台扫描、索引快照、锁内交换状态。

## 4. 仓库与交付架构

### 4.1 两个仓库的归属

```text
switchly/
  Sources/Models/Plugins/                 # 协议模型、安装状态、授权模型
  Sources/Services/Plugins/               # Registry、Host、Runtime、安装及授权
  Sources/Views/                         # 原生通用组件与管理页
  Plugins/api/                     # 拟新增：协议、能力清单、兼容规则
  Plugins/sdk/            # 拟新增：生成类型、definePlugin、UI 构建器
  Plugins/cli/            # 拟新增：开发和契约检查
  Plugins/create-switchly-plugin/# 拟新增：最小模板
  Plugins/bundled-plugins.lock.json
  Tests/...                      # 通用行为测试，无具体插件算法

switchly-plugins/
  plugins/
    music-controls/              # manifest、src、assets、locales、tests
    weather-gacha/
    whale/
  catalog/                       # 官方目录元数据，不是执行代码
  scripts/                       # 构建、验证、产物索引
  package.json                   # workspace；SDK 为版本化开发依赖
  <包管理器锁文件>
  README.md / CONTRIBUTING.md / AGENTS.md
```

SDK 与协议由宿主维护、发布，插件仓库只消费版本化 SDK；不在两个仓库各维护一份类型。不必第一天再拆第三个 SDK 仓库。

宿主保留 Apple Music 系统适配器、受控文件读取器、天气快照服务、Scene 渲染器。这些是系统能力实现；曲风抽取、卡片概率、角色姿态、Harness 会话格式解析、素材和专属文案都属于插件。不能为追求“零 Swift”把权限执行权下放到任意脚本。

`pickRandomTrack` 一类偏具体方法先保留兼容。只有第二个实际用例证明需要时，才演进为有上限的查询与播放 API，避免把迁移变成媒体平台重写。

### 4.2 预装产物的构建路径

```text
插件仓库固定提交 + 依赖锁
    → 独立构建/业务测试/公开协议校验
    → 每插件版本包 + 文件哈希清单 + 来源信息
    → 宿主预装锁定清单（ID、版本、提交、包哈希、协议范围）
    → 构建预备步骤将本地已验证产物放入忽略的生成目录
    → Xcode 资源阶段复制产物到 App/Contents/Resources/Plugins
    → App 签名与公证
```

建议使用固定 Release 产物消费；不把插件仓库作为 Swift 源文件夹嵌回，不将 Git submodule 当作完成解耦的证据。开发环境可通过参数提供本地外仓产物目录，CI 可先获取固定产物；两者共享哈希校验。

- `make build` 不静默访问网络；预装产物缺失时给出准备步骤，或者使用明确的“无预装开发构建”选项。正式发行缺产物必须失败，不能悄悄漏装。
- 下载仅发生于开发/发行流水线，不自动赋予运行中的 App 联网能力。无预装构建和发行构建均需真实验证。
- `project.yml` 改为生成产物路径后运行 `make generate`，审查 Xcode 工程差异；代码签名之后不修改 App 包。
- 同版本不同哈希视为不一致，拒绝覆盖。制品应能追溯提交、许可证及资产来源。
- 私钥不进仓库、不交给 Agent；本阶段只设计验证规则，未来签名接现有受控发行环境。

### 4.3 新增预装插件的工作流

1. 在插件仓库新增目录，用公开 SDK 完成开发、业务与权限降级测试。
2. 审核 manifest、资源许可、匹配范围、性能预算、双语说明和所需能力。
3. 发布该插件不可变版本产物，更新目录索引。
4. 在宿主 PR 只更新预装 lock/策划清单：选哪个版本、是否预装、首次默认状态。
5. 集成测试用发行产物加载，不从插件源码相对路径加载。
6. 下次 App 发布带入；已有用户的显式禁用、授权与配置优先于新默认值。

若新增插件需要宿主尚未提供的能力，应先提出 API 扩展并落宿主协议，再发布依赖该能力的插件；这是合理的能力依赖。

## 5. 插件管理机制

### 5.1 身份、来源与状态分离

建议安装记录至少包含：`pluginID`、`publisherID`、版本、包摘要、来源、获取渠道、API 范围、安装时间、活动版本与上个健康版本。插件自己填写 `publisher` 只是声明，“官方”标识必须来自宿主信任的发行清单或签名验证。

不能把所有状态塞入一个枚举，建议分四个轴：

| 轴 | 示例 |
| --- | --- |
| 包状态 | 已安装、校验失败、不兼容、候选新版 |
| 用户意图 | 已启用、已禁用、预装包被移除 |
| 授权状态 | 完整、缺必需权限、缺可选权限 |
| 运行状态 | 未激活、就绪、运行中、挂起、错误隔离 |

管理快照必须包含无法加载的包；manifest 损坏时用安装记录或目录名作为回退身份，保留结构化错误码与可操作提示。

### 5.2 本地存储与活动版本

建议逐步升级用户目录，旧平铺目录需兼容导入，不能直接更换路径导致旧插件消失：

```text
Application Support/Switchly/Plugins/
  Plugins/<plugin-id>/<version>-<digest>/
  staging/<transaction-id>/
  installed.json                 # 包记录与活动指针，原子写入
```

预装包仍只读位于 App 内；用户配置和授权继续由 `SettingsService` 持有，安装数据库只记录包与来源，不复制第二套用户偏好。开发目录保存单独引用记录，不扫描任意外部路径。

同 ID 候选解析规则：

1. 每个插件 ID 在当前用户配置中只有一个活动版本。
2. 用户安装的同发布者、验证通过、兼容版本可显式替代预装版；不依据版本号静默抢占。
3. 同 ID 不同发布者、来源不明或签名不符，显示冲突，不能继承旧授权。
4. 开发覆盖只有显式开启开发模式并选择目标后生效；退出开发模式回到原版本。
5. 回退预装/上个版本前重新校验兼容性、权限范围与配置版本，避免配置降级破坏。
6. 预装清单移除某插件不等于允许删除用户另行安装的版本或配置。

### 5.3 安装、更新和回滚

第一期支持本地包导入、目录导入和开发目录链接，原目录入口保留为高级操作。

安装事务：选包 → 在 staging 解包/复制 → 校验 schema、协议、入口/资产路径、文件数、总字节数、解压预算、哈希与来源 → 展示权限差异 → 写不可变目录 → 原子切换活动指针 → 加载健康检查。任何失败保持旧版可用，删除本次 staging。

解包拒绝绝对路径、`..`、设备文件、逃逸符号链接；资产与入口校验都要解析真实路径，不能只做字符串前缀。限额应在解包和读取阶段执行，不能等内存已耗尽再验证。

- 更新与安装共用事务，不另造平行加载器。新增必需权限时保留旧版运行，候选新版等待确认；可选权限缺失允许降级。
- 更新时先停止新调用并排空有界在途动作，再切换；带代次标识丢弃旧结果，不能重复执行播放等有副作用操作。
- 保留一个健康旧版本供本地回滚；用户数据若需迁移，先做受限快照并定义反向兼容策略，不能只回滚 JS。
- 运行错误不会无限自动重启。显示错误、允许手动重试；错误隔离状态与用户“关闭”分开。
- 用户插件可卸载，默认保留配置；“同时删除数据”单独确认。预装插件可关闭、逻辑移除、恢复；不修改已签名 App 包。

### 5.4 授权机制

官方与第三方使用相同 capability 检查入口。初次预装可以由经审核的分发策略授予现有低风险能力，但不能允许外包自行决定信任；`fs.read` 等敏感能力继续逐项确认。

- 授权绑定“ID + 已验证发布者 + 能力 + 资源范围”，而不只是 ID 或权限字符串。
- 同发布者常规更新可继承未变化的授权；新增权限、扩大目录、改变目标应用范围都重新比较，不能同名能力静默扩权。
- 区分必需和可选权限。鲸娘缺目录授权时保留待机动画；天气缺在线数据时保留手动模式。
- 插件申请目录 ID 与用途，宿主通过文件夹选择器确认实际根目录；manifest 推荐路径仅作为提示，不能替用户授予。沿用敏感目录拒绝策略，根目录被替换或符号链接变化需重新核验。
- 撤销授权立即停止相关订阅、取消未开始动作并重建受影响上下文。运行中能力调用也核验授权代次，避免仅在 VM 创建时检查。
- macOS 辅助功能、屏幕录制、自动化授权与插件授权分开呈现；插件获准不代表系统已经允许。

### 5.5 离线与在线目录

一期“发现”只浏览随 App 或用户导入的本地 catalog，条目带来源版本和日期；不提供虚假的在线更新提醒。浏览器可由用户主动打开官方仓库页面，下载后导入本地包。

在线索引/下载器列为后续独立选项，不能在当前隐私承诺下顺手加入。若以后批准，需同步 `PRIVACY_POLICY.md`、AGENTS 和发行说明，明确默认关闭、请求域名、数据内容、手动/定时策略、签名与吊销规则。插件运行时继续无网络；市场服务与插件 capability 不混为一谈。

### 6.1 信息架构

保留偏好设置“插件”入口，内部改成 **顶部工具栏 + 插件列表 + 所选插件详情**。筛选用菜单/分段控件，避免在现有偏好设置侧栏之外再叠一个常驻大侧栏。

### 6.2 列表与操作

- 每行显示图标、名称、发布者/来源、简短状态；版本等次要信息按可用空间显示。列表不展开设置表单、不显示长篇说明。
- 搜索覆盖本地化名称、ID、作者、标签、目标应用名与 bundle ID；筛选支持启用、禁用、待授权、错误、不兼容、预装、用户安装、开发目录、目标应用。
- 按名称、状态、安装时间排序；默认稳定排序，状态变化不使选中行突然跳走。
- 常用视图为“全部、已启用、需处理、开发中”；分类/目标应用为筛选条件，避免一个插件出现在多个分组导致操作混淆。
- 支持多选启用/禁用/卸载；批量授权按插件展示差异，不能一个开关全部授敏感权限。官方预装“移除”与用户包卸载使用不同说明。
- 详情只创建选中插件的设置控件，离开详情取消预览与诊断订阅。插件管理页本身不激活所有插件。
- 诊断给出最后错误、兼容性、权限缺口、当前匹配/槽位状态；日志导出只含脱敏结构数据，不包含窗口标题、目录内容或 JS 任意输出全文。

### 6.3 布局、键盘与规模验收

- 当前偏好设置为固定 `760×560`，不得硬塞三列。先测量扣除宿主侧栏后的可用宽度；足够则列表/详情两栏，不足则列表进入详情并有返回路径，允许窗口按屏幕边界调整大小。
- 列表使用原生 `List` 或延迟构建；搜索基于后台生成的索引，不在每次按键时扫描磁盘或运行 JS。千级目录只增量读取变更包，源码在激活时读取。
- `⌘F` 聚焦搜索，方向键选择，Return 进入详情，Escape 返回/关闭弹层；说明图标用真正 Button，所有无标签控件补无障碍标签。
- 验收数据集：0、3、100、1000 个 manifest，含损坏、长名称、多语言、重复 ID、不同 API、待授权项。分别检查首屏、搜索、筛选、多选和错误恢复。
- 建议性能目标：在记录型号/系统/构建的参考机上，1000 项热缓存首屏 p95 ≤300ms，搜索反馈 p95 ≤100ms；冷扫描分批显示，不阻塞主线程。它们是待实测校准的目标，不是当前数据。
- 管理 UI 的表现与运行时压力分开测：1000 已安装、100 同目标匹配、最多若干被用户选中展示。最终同时活动数量由真实 Dock 面板预算决定。

## 7. API 规范化与功能扩展

发展路线详见 [插件 API / SDK 能力开放路线与执行计划](plugin-api-roadmap.md)：按 Magpie、Raycast 的能力和权限模型进一步细化 R0–R5、授权层级、能力目录与前两个迭代 Backlog；新增接口仍为待裁决规划，不表示已实现。

### 7.1 唯一契约来源

建议 `Plugins/api/` 保存版本化协议描述：manifest、Context、UI/Scene 数据结构、动作、错误、生命周期、权限、预算与 capability 状态。生成 JSON Schema、TypeScript 类型、公开文档和一致性测试数据；Swift 负责语义与安全校验，并对同一组正反例做互操作测试。

不要求一次写出能自动生成全部 Swift Runtime 的代码生成器。先定义最小契约格式与共享测试样本，防止“Schema 合法、Swift 拒绝”或相反；逐步生成机械部分。

每个能力需记录：名称、协议引入版本、实现状态、所需权限、平台/目标限制、方法签名、错误、预算、示例、测试 ID 与弃用替代。状态只允许 stable / experimental / planned / deprecated，planned 不生成可调用 SDK。

### 7.2 版本与兼容策略

- 分开 `manifestVersion`（包格式）、`apiVersion`（运行协议主版本）、插件 SemVer、SDK SemVer、宿主版本范围；SDK 更新不必强制宿主升级。
- 保留 v1/v2 读取与适配。字段改名、权限语义改变、生命周期改变、action 事件结构改变等破坏性变化集中到下一主协议（可命名 v3，待裁决）。
- 插件声明必需能力及可选能力；宿主同时检查版本与具体 feature，不仅判断 `1...2`。不兼容在安装前说明缺什么，不能等 JS 抛错。
- 向前兼容规则区分 manifest 可选元数据与安全字段：安全字段不认识要拒绝/待授权，未知可选展示元数据可忽略；UI 未知节点不能无声改变含义。
- 稳定 API 变更附兼容测试、迁移指南和弃用期；建议至少保留两个正式 App 小版本且不少于 90 天，实际以发行节奏裁决。旧 API 移除前目录可检索受影响插件。

### 7.3 分层 API 与优先级

| 层 | 本期必须收敛 | 后续按需扩展 | 明确边界 |
| --- | --- | --- | --- |
| 基础 Context | app/window 快照、locale、主题/减少动态效果、能力探测 | 屏幕与布局约束快照 | 不给任意系统对象和完整窗口内容 |
| 生命周期 | activate、可见性变化、suspend/resume、dispose、settingsChanged 的明确语义 | 有配额的事件订阅 | 每个监听、Timer、任务有清理所有者 |
| UI/Scene | 已有四个槽位、通用组件、Scene、动作命名空间、资产加载 | 真正需要的 completion 事件与 easing | 不开放逐帧 JS、任意 HTML/CSS |
| 设置 | toggle/select/number 的完整验证与统一值存储、分组、本地化 | string、用户选目录、可见条件，逐项引入 | 宿主不理解插件自定义 key 的业务意义 |
| 本地状态 | 有配额的插件私有 KV、版本化数据与清除入口 | 受限迁移函数 | 不把完整 UserDefaults 暴露给插件 |
| 媒体 | nowPlaying/control/library 的类型、错误、目标支持与取消语义 | 明确需求后的查询、媒体事件 | AppleScript 固定模板仍由宿主控制 |
| 天气 | 标准只读快照、可用性、更新时间、宿主数据源设置入口 | 新来源必须另行隐私裁决 | 插件不提交 URL、不直接联网 |
| 文件 | 当前 list/stat/readText/scan/isLocked 的类型、根目录令牌和限额 | 有界 watch，需句柄及停止语义 | 不新增 fs.write、不读敏感目录 |
| 窗口 | 当前 window/app 只读快照先准确公开 | focus 如确认需要，再接现有 AX 服务 | 不把“应用激活”报告为窗口聚焦成功 |

能力扩展流程：真实插件用例 → 写中立需求 → 核验已有服务 → 协议及预算/错误设计 → 宿主与 fake 测试 → 外仓示例验证 → stable。不能只因为某插件需要一个字段，就在宿主按它的 ID 加分支。

### 7.4 生命周期、调度与隔离

1. **安装期与运行期分离**：启动扫描元数据，索引 `bundleID → 插件候选`；目标预览可见时只激活用户选中且获授权的贡献项。
2. **可见会话分离**：同插件可有多个 window 实例，各自有 `instanceID`、订阅及取消令牌，不让两个窗口相互覆盖状态。
3. **隐藏即挂起**：取消宿主刷新与订阅，冻结或取消插件定时器；保留有上限的小状态。重开根据截止时间重新计算动画，不在后台持续计时。超过空闲预算或 LRU 上限释放 VM。
4. **事件优先、独立轮询兜底**：天气/媒体/设置变更触发失效合并；必要轮询按插件各自截止时间，不取最短周期刷新所有插件。invalidate 合并并限制并发，旧结果按代次丢弃。
5. **展示配额先于执行**：槽位排序由用户控制，不以目录字母顺序作为长期产品规则；单槽位保留现有最多三项上限作为起点，溢出项显示“未展示”，不创建/刷新其 VM。
6. **JSC 边界诚实说明**：同进程 JSC 适合受审核、受控插件；不能把软超时当作不可信代码的硬资源隔离。

若目标升级为开放安装未经审核的社区插件，建议将 JSC 执行迁至受限插件宿主进程，使用版本化 IPC、能力令牌和受控沙箱。主 App 持有系统权限，helper 不继承任意文件/网络访问，能被终止和重建。单共享 helper 只能提供整个插件宿主的故障恢复；按插件独立 helper 隔离更好但成本更高，需测启动/内存与 macOS 12 兼容后决定。进程隔离与安全沙箱是两件事，二者都需验证。

同步死循环实验仅能在可杀死的独立测试进程执行，不应直接挂住主 App。开放市场以该隔离门禁通过为前提；不阻塞三个经审核官方插件的首期源码外迁。

### 7.5 权限和错误的一致语义

下一协议统一：未授权能力不注入业务方法；`ctx.capabilities` 可查询 supported / granted / available 及原因。可选权限被拒绝时按文档降级；旧版本通过兼容层保持行为。

结构化错误建议包含 `code`、`messageKey`、`retryable`、脱敏详情。至少区分 permissionDenied、systemPermissionRequired、unsupportedTarget、targetGone、cancelled、rateLimited、invalidArgument、resourceLimit、timeout、internal；不要所有情况都返回 null。

时间统一声明 Unix 秒或毫秒，字段名/类型写清；资源上限、超时与并发限额由宿主配置公布。所有外部文本、节点数、JSON 字节数、嵌套深度都在进入高开销解码/绘制前限制。

### 7.6 天气解耦的具体落点

宿主保留用户显式开启的 `OnlineWeatherService` 和通用设置 UI，插件 manifest 通过受控贡献项声明“使用 weather.current，提供打开该数据源设置的入口”。任何获准插件都能使用，不再判断天气抽卡 ID。

插件内负责手动天气及“使用手动/宿主数据”的选择，在线快照不覆盖手动值。旧用户因宿主回写产生的现有选项原样保留，首次迁移不覆盖；未来关闭在线天气即回到保留的手动值。城市、刷新状态及错误属于宿主数据源，不复制到每个插件设置。

## 8. 让 Agent 能独立开发的工具链

目标流程：读取公开能力清单 → 创建模板 → 编写类型化插件 → 在 fake Context 中测试 → 用真实宿主测试工具验证 → 本地加载 → 授权与真实场景验收。无需打开宿主 Swift 源码猜接口。

拟新增命令如下，**当前均不存在，不是本次执行或通过的命令**：

| 拟议命令 | 作用与输出 |
| --- | --- |
| `create-switchly-plugin` | 最小模板，固定 SDK 与协议，无不支持的浏览器/Node API |
| `switchly-plugin api describe --json` | 从协议包读取能力、状态、权限、预算、版本；离线可用 |
| `switchly-plugin validate` | schema、设置 key 唯一、资源、入口、本地化、兼容范围、包大小检查 |
| `switchly-plugin build` | TS 打包为 JSC 可运行 JS，无 Node built-in、原生模块和运行时下载 |
| `switchly-plugin test` | 插件业务测试 + 合成 Context；不承诺模拟真实 AX 或系统自动化 |
| `switchly-plugin verify --host <测试工具路径>` | 在与发行版共享实现的 JSC/解码工具中验证输出、权限、资源预算 |
| `switchly-plugin dev --profile <独立测试配置>` | 仅监视显式开发目录，定向重载单插件，错误保留上个可用产物 |
| `switchly-plugin pack` | 可安装包、文件哈希清单、来源与许可信息 |
| `switchly-plugin doctor` | 诊断宿主/API/包/授权，不输出真实私密配置 |

测试工具不是复制 Runtime 的 JS 版。它应链接或复用真实 JSC 桥与 Swift 解码器，只替换系统能力为 fake，通过独立进程承受卡死测试。

插件仓库的 `AGENTS.md` 明确：只用 stable 接口；experimental 需显式声明；禁止读用户真实会话/凭据；所有文件测试用合成夹具；遇到 API 缺口提交能力提案，不回宿主塞 ID 分支。

协议变更 CI 同时检查生成物漂移与外仓固定插件版本；SDK 测试通过只证明开发契约，真实宿主加载证明互操作，Dock/AX 真机验证证明系统行为，三者分开报告。

## 9. 多轮解耦审计与验收门禁

外置化至少过四轮，每轮失败都应能定位到具体契约，而不是只看目录结构。

| 轮次 | 检查 | 通过标准 |
| --- | --- | --- |
| A：源码与业务 | 宿主非生成代码搜索三个插件 ID、抽卡/角色/会话字段；检查测试与本地化 | 除预装 lock、迁移表、文档及包集成引用等明确白名单，无插件业务分支或资产 |
| B：仓库独立 | 干净环境只取插件仓库与 SDK/测试工具发布包，构建全部插件 | 不使用宿主源码路径、`@testable import Switchly` 或私有模块 |
| C：协议同权 | 相同包分别经预装和用户安装路径加载；换插件 ID/素材、拒绝权限、回滚 | 同授权下 API 与输出一致；无凭 ID 取得权限或专属 UI |
| D：真实宿主 | 空预装构建、固定产物加载、真实 Dock、设置/授权变更、多插件同槽位 | App 可独立运行；行为对齐；关闭后活动回落；错误不影响其他插件 |

具体回归矩阵：

- **配置迁移**：旧 `pluginGrants/pluginSettings/pluginValues` 缺省、非法类型、越界值、重复 key；统一存储迁移必须幂等，失败保留旧配置。
- **供应链/安装**：损坏包、篡改、同版本不同哈希、重复 ID、来源冒充、路径逃逸、过大包、进程中断、磁盘写失败、回滚失败。
- **权限**：缺失/新增/撤销权限、同名目录扩围、发布者变化、macOS 系统权限缺失；不能通过预装来源绕过敏感能力。
- **运行**：两个插件同 action ID、两个窗口实例、切换目标时迟到结果、重复启停、订阅泄漏、同步死循环（独立子进程）。
- **插件行为**：Music 播放/喜欢/封面；天气手动与在线切换、抽卡及曲库；鲸娘合成会话目录、未授权待机、角色素材及动画。算法断言在外仓，真实系统交互验证在宿主集成流程。
- **界面**：0/3/100/1000 项、长标题、错误、待授权、键盘与 VoiceOver；浅色/深色/跟随系统、玻璃开关、减少动态效果，真实截图人工读图。
- **性能**：启动扫描、已安装但未激活、100 同目标候选、可见动画、隐藏状态、反复开关 50 次、VM 空闲释放。记录机型/系统/构建/目标 App，不用离屏 PNG 编码时间替代真实帧耗时。
