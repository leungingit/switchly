# 音乐媒体桥：MediaRemote 最小接入设计

> 2026-11-10。状态：MR-T01～T04 已实施；MR-T05 的当前机器注入式真实面板与浏览器验证、MR-T06 的候选打包／双架构 Adapter 读取／Intel 宿主编译已完成。跨系统真机、真实睡眠、完整视觉基线与正式签名公证仍待完成，整体门禁未通过。默认主 App 已按 MR-D11 接入组合桥并离线打包，真实 Dock 悬停验收见[正常启动接入记录](../../reviews/music-mediaremote/music-mediaremote-default-startup-2026-11-10.md)；不提交、不推送。证据见 [T01／T02](../../reviews/music-mediaremote/music-mediaremote-implementation-2026-11-10.md)、[T03／T04](../../reviews/music-mediaremote/music-mediaremote-t03-t04-2026-11-10.md)、[T05／T06 与架构审查](../../reviews/music-mediaremote/music-mediaremote-t05-t06-architecture-2026-11-10.md)。

## 1. 依据与范围

[本地探针记录](../../reviews/music-mediaremote/music-mediaremote-probe-2026-11-10.md)证明：当前 macOS 27.2 上可取得 Apple Music 流媒体封面；浏览器能抢占系统媒体会话，暂停浏览器也不立即归还；新歌标题与封面存在不同到达时间。探针不是正式 App、最低系统或发行签名的验证。

当前约束来自 [API 参考](../plugin-api-reference.md)、[历史设计](../dock-preview-plugins-design.md) D02 / D09、`MediaBridging`、`MusicLibraryPlaying`、`PluginHost`、`PluginRuntime` 与 `DockPluginOverlayModel`。

本轮目标仅为 Apple Music：增加宿主拥有的本地 MediaRemote 读取来源，解决流媒体封面，同时保持按 Dock 应用读取、定向控制、喜欢与资料库能力。插件仍调用现有 `ctx.media`、声明 `{artwork:true}`；图片字节不交给 JS。不增加全局播放器模式、其他播放器匹配、网络封面搜索、AX 遍历、OCR、Rust 依赖或任意子进程接口。

本文 MR-Dxx / MR-Txx / MR-Gxx 为独立编号，避免与原插件台账的 Dxx 冲突。以下以任务表区分已实现的独立组件与拟接入契约；未实施项不能解释为现有能力。

## 2. MR-D01：沿用桥接边界，分离读取与控制

| 职责 | 拟实现位置 | 契约 |
| --- | --- | --- |
| 系统事件采集、增量解码 | 新增宿主 Adapter 进程封装及协议 | 输出内部事件；不认识插件 ID，不发送播放命令 |
| 来源选择、歌曲代际、封面校验 | 实现现有 `MediaBridging` 的组合桥 | 只支持本轮目标 `com.apple.Music`；向消费方提供完整快照 |
| 播放控制、喜欢、资料库 | 复用 `MusicAppleScriptBridge` | `perform` 与 `MusicLibraryPlaying` 继续定向操作 Music；不使用系统媒体键或 Adapter 的 `send` |
| 授权、生命周期与快照读取 | `PluginHost` / `PluginRuntime` | 复用已授权能力；注入依赖，不新增散落的单例 |
| 发布与渲染 | `DockPluginOverlayModel` | 同批文字、进度和封面读取同一快照并整组发布；2D 与 3D 共用 |

组合桥必须继续提供或显式转发 `MusicLibraryPlaying`。当前 Host 通过 `mediaBridge as? MusicLibraryPlaying` 注入资料库，直接替换为只实现 `MediaBridging` 的类型会静默丢失该能力。沿用既有串行队列和播放状态 reconciliation，控制后重新采样；不把乐观播放状态当成换歌确认。

## 3. MR-D02：目标应用优先，系统来源不匹配就回退

1. 目标来自现有 `PluginRenderContext.bundleID`，插件不能指定任意查询目标。
2. Adapter 的 `bundleIdentifier` 必须精确等于目标，进程身份必须匹配当前运行的 Music。来源缺失、无法确认或目标应用退出时，不能使用该系统快照。
3. 浏览器的 `parentApplicationBundleIdentifier` 不得用于冒充 Music；不做名称、窗口标题或应用图标的模糊匹配。
4. 浏览器抢占后，清除当前系统来源的封面资格，转为 Music AppleScript 整组数据；Music 流媒体没有可信封面时显示占位图。浏览器暂停依然按来源不匹配处理。
5. 系统会话返回 Music 后重新建立歌曲身份，等待该歌曲的图片，不直接恢复此前系统会话的图片。
6. Adapter 不可用不等于 Music 不在播放。读取失败、无会话、来源不匹配、无自动化授权、目标退出分别记录原因；对 JS 保持现有 `NowPlaying | null` 和错误语义。

全局 `auto` 模式不在本轮引入；来源过滤只保证不会显示其他应用，不能使 MediaRemote 获得任意非当前会话。

## 4. MR-D03：以歌曲代际隔离异步结果，禁止无条件按字段合并

宿主内部增加不可变媒体快照，字段至少包含：目标 Bundle ID、进程身份、来源、流连接代际、歌曲代际、内容修订号、来源内歌曲标识、标准 `NowPlaying`、封面状态及内容 token、进度采样时间与速率。标识保持内部使用，不扩展公开 JS 对象。

标识规则：

- Music 的 persistent ID 与 MediaRemote 的 `uniqueIdentifier` / `contentItemIdentifier` 属于不同命名空间，不直接比较或互相覆盖。
- 系统来源、进程身份、流连接或来源内歌曲标识变化，以及没有标识时的歌曲元数据变化，均须重新判断歌曲代际；不能只按标题判断同一首。
- `stream` 的非增量事件替换全部状态；增量事件合并字段，显式 `null` 删除字段，未出现的字段保持不变。空完整快照清空旧状态。任何流重建都从空状态开始。
- 发生换歌、控制请求 next/previous、来源切换、目标重启、授权撤销或连接失效时，先撤销旧图片资格。晚到的旧代际解析、图片解码或 AppleScript 结果不得恢复旧图。
- 进度和封面变化只更新内容修订号；进度每秒推算不制造新的歌曲代际。

### 跨来源配对的保守条件

优先让 MediaRemote 的标题、歌手、专辑、时长、进度和封面作为同一来源的数据组。喜欢状态只能来自 Music；若要补入，必须先完成配对，不能按“哪个字段非空就用哪个”拼接。

首次配对使用 Music 采样前后夹住一份冻结的系统快照：两次 Music 采样的进程身份、persistent ID、标题、歌手、专辑不变，期间系统歌曲代际不变；两来源的标题、歌手、专辑要求完整且一致，时长都有效且差值不超过 1 秒（容纳本次观察到的整秒与小数差异）。不以播放位置相等作为条件。喜欢状态采样也需检查读前、读后的 Music 曲目身份。

这是**有界的一致性检查，不是跨来源歌曲 ID 的权威映射**。同元数据不同版本、缺字段、相同标识被复用或正在切换时不能声称唯一匹配；已知歧义、身份不足或检查失败时整组回退 AppleScript，并撤销 MediaRemote 图片。首次夹取完成前也使用回退组，不长时间阻塞插件 render。已建立配对只在当前连接、进程与歌曲代际内复用。

首版不减少 Apple Music 已有喜欢能力：无法安全配对时，整组使用现有 AppleScript 数据与喜欢状态，不能为了显示封面而伪造 `liked=false`、静默移除喜欢按钮。自动化未授权时也维持现有降级，不在本轮引入“仅 MediaRemote 可读”的新产品状态。

**MR-G01 的必要研究项**：用可重复夹具与真实切歌检查此配对策略，特别是同标题不同版本。如果不能满足拒绝错配要求，继续占位或回退，不放宽匹配条件凑通过率。若需要权威 ID 映射或产品能力调整，补充设计后再实施。

## 5. MR-D04：一次渲染固定一份快照，整组发布

当前 `DockPluginOverlayModel.render` 先赋值 `slots`，再 `await host.artwork(for:)` 并发布图片；现有 `generation` / `renderRevision` 不能证明这两次读取属于同一首歌。

拟调整的内部流程：

1. Host 在已授权的可见消费开始时持有读取兴趣；每批叠层渲染取得一个不可变媒体读取上下文，所有 runtime 在这一批 `render` 中的 `ctx.media.nowPlaying()` 都读该快照。
2. 读取上下文仅经宿主内部参数传递。复用现有 `PluginRenderContext` / render 调用链，不将 Data 或内部 token 写入 JS 对象。只授权 `media.control` 的 runtime 不能因此取得歌曲元数据。
3. 插件渲染期间如有新歌曲或来源事件，旧批次到达提交点后丢弃，并合并请求下一批；图片补回也触发宿主失效通知，不等待每秒轮询。新请求合并，禁止无界排队。
4. 构造包含 slots、动作归属、图片和 token 的单个展示状态，在主线程一次发布。保留现有 generation / renderRevision，增加媒体读取上下文有效性检查。不能先发布新 slots 再等待图片。
5. 换歌时立即撤销旧封面；可以暂时保留此前文字或显示占位，但新标题绝不能配旧封面。收到新封面后整组重新渲染。
6. 快照没有封面时明确发布 nil；不能因为新树未包含 artwork 节点就残留上一批图片。图片 token 包含歌曲代际及内容身份，不使用 NSImage 对象地址。
7. 同一歌曲的多个槽位／插件共用该批快照。普通 2D image、Scene 与 scene3d 表面使用同一封面 token，图片变化才更新纹理。
8. `onAction` 不固定使用上一批 render 的快照：控制动作仍检查当前目标和授权，完成后失效重读。期间的 nowPlaying 查询按动作当时的快照返回，不能用 render pin 遮蔽真实控制结果。

这些变动只调整内部调用与展示状态。公开 `ctx.media` 字段、插件 manifest 与 `Plugins/api/capabilities.json` 不因新增数据来源而升版。Preview Worker 的 fixture 媒体桥也需实现相同内部上下文语义，但仍使用夹具，不能意外启动真实播放器或 Adapter。

## 6. MR-D05：进度、封面与资源预算

- 系统时间戳先结合接收时的墙钟计算基准进度，再以单调时钟推算；`position = clamp(base + monotonicDelta × rate, 0, duration)`。暂停、seek、歌曲变化和新进度事件重建锚点。无效日期、非有限数或不合理时间差不继续外推，回退有效采样。
- 歌曲进度和控制状态不因为封面未到而阻塞。没有图片时保持占位；封面不单独启动高频轮询。图片缺失不增加 AppleScript 重试频率。
- 图片只在宿主内存缓存，不写磁盘、不下载 URL、不向外发送曲名。保持现有对 AppleScript `URL track` 图片的拒绝策略；本次单样本成功不足以撤掉保护。
- 图片解码前检查格式、尺寸和预算，复用现有图片验证／缩放逻辑和共享预算；禁止把任意 Base64 直接交给主线程的 `NSImage`。已实现的 `MediaRemoteBudget` 限制单行 JSON 至多 12 MiB、Base64 转换后的压缩数据至多 8 MiB，并在追加行缓冲前检查预算。图片格式、像素及解码后内存检查由 MR-T04 的 `MediaArtworkDecoder` 完成：只接受单帧 PNG／JPEG／HEIC／HEIF，源最长边 4096、像素数不超过 4096²；缩略图最长边 512，实际绘制为 RGBA8，按 bytesPerRow × height 限制为 1 MiB。状态机自身仍只持有候选字节。
- 当前展示保留一首有效封面；近期已解码封面按 MR-D12 在同一采集会话内有界复用，仍只允许一个在途解码和一个最新待解码结果。新代际取消或丢弃旧解码。读取 stdout 采用有上限的增量行缓冲；超过限额按失败处理并释放缓冲，不能等到换行后才检查。
- stderr 只输出脱敏、限速的错误原因，不把原始 JSON、Base64、歌曲标题或用户路径写入常规日志。

## 7. MR-D06：进程所有权与失效回退

一个 Host 共享一条 Adapter 流。兴趣由已授权、当前可见且会读取媒体的运行态持有；首次兴趣启动，最后兴趣撤销立即停止。`stop`、授权撤销、reload、unmount、退出及 deinit 均释放自己的兴趣；其中一个消费者结束不影响其他有效消费者。挂起的 VM 不保留采集兴趣。

用明确的 acquire / release 句柄与协议注入实现，不在热路径创建进程或读取磁盘。进程的 stdout/stderr、观察者、Task、超时及退出回调均由进程封装持有。Parser 和图片解码不在主线程；UI 发布在主线程；锁内不执行脚本、I/O、回调或进程等待。

状态为：停止 → 启动中 → 有效流 → 失败回退。失败或异常退出清空该连接数据，当前可见期间不自动无限重启；下一次从零兴趣转为有兴趣时才允许再尝试。退出先请求 SIGTERM，1 秒后仍未退出才清理该子进程；不使用 shell 拼接命令，也不杀其他实例。

启动后 2 秒内连初始完整事件都没收到，视为启动失败；收到合法空快照代表没有媒体，不能因为歌曲没有变化或图片尚未出现而按静默超时重启。睡眠／唤醒使旧进度和连接资格失效，有兴趣时重建一次；失败仍回退。上述时间为初版预算，须以进程夹具测定。

只读来源不取消 Apple Events 对控制的授权要求；没有对应授权仍返回原有错误。不得自动添加 entitlement、关闭系统保护、修改系统守护进程或运行时联网下载修复脚本。

## 8. MR-D07：依赖、构建与发布边界

Adapter 是宿主依赖，不放入外仓音乐插件，不让 JS 安装或运行。MR-T01 将原样源码固定在 `Vendor/MediaRemoteAdapter/upstream`，revision 为 `0e82bf1c44ec39554fbfc402ec88a48c6ae2a0fd`，保留 BSD-3-Clause 许可证；`source.json` 记录逐文件哈希和归档来源。`Scripts/mediaremote-adapter.py` 完全离线校验／构建，拒绝缺失、额外、篡改或符号链接输入，不自动刷新清单。

以下为 MR-D11 之前的候选阶段记录（普通构建行为已被 MR-D11 取代）：`make build`、`build-release`、`test`、`test-unit` 仅离线校验源码；显式执行 `make mediaremote-adapter-build MEDIAREMOTE_OUTPUT=...` 才用 Xcode 自带 clang 编译双架构产物，无 CMake 依赖，不复制进普通构建的 App。`make mediaremote-adapter-stage` 可显式在新路径创建待签名验收的候选 App，将依赖复制到其 `Contents/Resources/MediaRemoteAdapter`，不修改输入或默认来源。`make mediaremote-adapter-test` 覆盖清单完整性失败分支。本轮默认桥接、公开 API、插件锁及 Preview 行为均不变。

调用系统 `/usr/bin/perl` 与 App 包内固定脚本、framework 路径；不链接该 framework 到宿主进程，不依赖用户安装 Homebrew、CMake 或 Perl 模块。上游终端 ad-hoc 测试成功不等于发行包通过：须验证实际包内路径、嵌套签名、Hardened Runtime、公证和 clean-machine 运行。保留 AppleScript 回退，不假称私有接口稳定。

宿主主 App 需要该依赖；独立预览 App／Worker 使用 fixtures，默认不执行真实 Adapter，打包规则明确区分二者。本轮不改变插件锁文件、不更新外仓制品。只有确需改插件 JS 时才先在外仓 `npm test`、`npm run build`，再显式接受锁文件变化。

实施时同步 API 参考的宿主来源说明、README 的能力边界，以及 PRIVACY_POLICY 的媒体本地读取／Apple Events 用途。当前政策将 Apple Events 仅描述为窗口聚焦，不能据此解释实际音乐读取与控制；本轮先记录问题，不把未实施能力写成现状。

## MR-D08～MR-D10：本轮架构与候选包补充

- MR-D08：真实 OS 依赖统一在 `MediaRemoteAssembly` 装配，组合桥只保留选择与转发策略；默认 Host 不调用候选装配（此限制被 MR-D11 取代）。
- MR-D09：Session 的状态归并移到专用串行队列，展示有效性只读短锁缓存；Host 通过 `PluginRuntimeVisibility` 管理多个叠层的共享 VM，以通用 `PluginLifetime`／`PluginInvalidator` 复用释放与通知机制。
- MR-D10：显式 stage 只生成新路径下的待签名候选副本，拒绝覆盖宿主、Preview／Worker 和既有输出。候选不进入普通构建，不代表已完成发行签名（普通构建不打包的限制被 MR-D11 取代）。

具体问题、改动及证据见 [架构审查](../../reviews/music-mediaremote/music-mediaremote-t05-t06-architecture-2026-11-10.md)。
