# 应用活动时间线插件：方案与任务划分

> 状态：M0～M3本地实现与适用门禁已落地（2026-11-12），真实平台验收部分待完成；原2026-11-09草案保留，最新合同见第9节，证据见[实施验证记录](../reviews/activity-timeline-implementation-2026-11-12.md)。决策编号 `AT-Dxx`，编号越大越新；被取代条目保留并标注。

> 第1～8节为2026-11-09原始草案，保留历史，不再作为当前实现现状；第9节为有效合同，第10节为实施状态。

## 1. 目标与非目标

**目标**

1. 记录一天中切换到的前台应用及每段停留时长。
2. 按应用采样保存本地小尺寸截图。
3. 在插件独立面板中按上午 / 下午 / 日 / 月 / 年 / 自定义时间段查看各应用时长与截图。
4. 数据结构为后续 AI 工作总结预留接口。

**非目标（首期）**

- 不实现 AI 总结、不新增任何网络能力。
- 不做跨设备同步、导出到云端、团队统计。
- 不让插件 JS 直接持有截图文件或后台常驻。

## 2. 现状差距（依据 `plugin-api-reference.md`）

| 需求 | 现有能力 | 差距 |
| --- | --- | --- |
| 前台切换事件 | `AppActivationTracker` 只记各应用最近离开前台时间，供 `ctx.app.lastActiveAt` | 无持续的停留区间记录与持久化 |
| 停留时长 | 无 | 需处理锁屏、睡眠、空闲、快速用户切换 |
| 截图 | `ThumbnailService` + `ThumbnailDiskCache`（≤24h、≤64 MB、不留原图） | 插件不可访问；长期留存与现有隐私约定冲突 |
| 存储 | `ctx.storage` 单值 64 KiB / 总量 1 MiB | 不足以存放区间与截图 |
| 独立面板 | 插件仅渲染 Dock 预览槽位，隐藏时挂起 Timer | 无插件面板 surface |
| 时间维度 UI | 声明式基础节点 | 缺分段选择、日期区间、条形图、网格列表 |

## 3. 关键决策

- **AT-D01 宿主采集、插件展示**：采集、截图、存储、聚合全部在宿主 Service 层；插件通过只读权限读取聚合结果。理由：后台常驻、截图权限、数据量与隐私边界都不适合放进插件运行时。
- **AT-D02 默认关闭、显式开启**：新增设置「记录应用活动」默认关闭；截图采样为独立二级开关，同样默认关闭。
- **AT-D03 复用而非平行实现**：前台切换复用 `AppActivationTracker` 的通知源（扩展为可订阅区间事件，而非另起监听）；截图复用 `ThumbnailService` 的抓取与预算，不另写截图管线；持久化写入方式参照 `UsageStatisticsService` 的合并写与原子写。
- **AT-D04 独立存储与独立预算（被AT-D09取代）**：活动截图与 24h 缩略图缓存分开存放（`~/Library/Application Support/Switchly/Activity/`），有独立的保留天数（默认 7 天，可选 1/7/30/90）与容量上限（默认 256 MB），超限按最旧优先清理；可一键清除。
- **AT-D05 隐私例外需文档先行（被AT-D08扩展）**：长期留存截图属于对现有「仅短期缓存」约定的新增例外，必须先更新 `PRIVACY_POLICY.md` 与 `AGENTS.md` 第 6 节再合并实现。
- **AT-D06 插件只拿引用不拿文件（由AT-D11细化）**：`ctx.activity.snapshots()` 返回宿主签发的不透明图片引用，由宿主渲染节点解析，插件无法读取像素或路径。
- **AT-D07 AI 总结默认本地**：二期优先评估本地方案（Vision OCR + 系统端侧模型）；如需云端，按天气例外的规格单独立项。

## 4. 数据模型（草案）

```swift
struct ActivitySession: Codable {      // 一段前台停留
    let id: UUID
    let bundleID: String
    let appName: String
    let start: Date
    var end: Date                       // 进行中时为最后心跳
    var endReason: EndReason            // switched / locked / slept / idle / quit / appTerminated
    var titleDigest: String?            // 标题摘要（截断+可关闭），不存完整标题
}

struct ActivitySnapshot: Codable {
    let id: UUID
    let sessionID: UUID
    let capturedAt: Date
    let fileName: String                // 本地 HEIC/JPEG 小图
    let pixelSize: CGSize
}
```

- 存储：按日分片 `sessions-YYYY-MM-DD.json`（或评估 SQLite，见 T1.2），截图在 `snapshots/YYYY-MM-DD/`。
- 聚合按本地时区计算，跨午夜的区间拆分到两天；上午 = 00:00–12:00、下午 = 12:00–24:00（可在设置中调整分界点，二期）。
- 停留短于阈值（默认 3 秒）不计入统计，但保留切换序列供调试。

## 5. 插件 API 扩展（草案，`apiVersion: 3` 候选）

- 新权限 `activity.read`（数据授权，用户单独确认）。
- `ctx.activity.summary({ from, to, groupBy: "app" | "hour" | "day" | "month" })` → `[{ bundleID, name, seconds, sessions }]`
- `ctx.activity.sessions({ from, to, bundleID?, limit })` → 区间列表（单次上限 500 条）。
- `ctx.activity.snapshots({ from, to, bundleID?, limit })` → `[{ ref, capturedAt, bundleID }]`，`ref` 用于 `image.activitySnapshot` 节点。
- 新 surface：manifest `surfaces: ["dockPreview", "panel"]`；宿主提供菜单栏入口打开插件面板（原 NSPanel 安排被 AT-D19 取代，使用标准 NSWindow，复用 `GlassEffect` 与主题）。
- 新声明式节点：`segmented`、`dateRange`、`barChart`、`grid`（可滚动缩略图网格）。
- 同步更新 `Plugins/api/manifest.schema.json`、`capabilities.json`、`plugin-api-reference.md`、SDK 类型与预览工具假数据夹具。

## 9. AT-D08～D14：2026-11-12 评审后实施合同

用户指令「按计划推进，先验证后完整实现」授权 M0～M3 的验证与完整实现，AI 留在二期。以下覆盖原草案对应部分，原文保留为历史。评审依据见 [2026-11-12 评审](../reviews/activity-tracking-plan-review-2026-11-12.md)。

- **AT-D08 计时与隐私**：宿主前台应用停留，默认关闭；不记录标题/调试序列。排除 Switchly 自身、无 bundle ID 及用户排除项，Finder正常计入。5分钟无输入后回退扣除最后输入后的区间，阅读/观看可能被排除，界面明示。锁屏、睡眠、会话失活任何一项阻断即停止，全部恢复后从当前时刻新开段。单调时钟计时，墙钟分桶，崩溃不补记至下次启动。有效短停留保留。原65行「3秒丢弃但保留调试序列」被本条取代。M1起即为新的本地活动记录隐私例外，原AT-D05被本条扩展。
- **AT-D09 存储与查询**：单一私有JSON存储，时长默认400天，可选1/7/30/90/400天，上限100000区间或64MiB，最旧先清；年视图仅查询实际保留数据，不推断过期内容。无另存永久聚合。截图独立1/7/30/90天，默认7天/256MiB、最长边640像素、单图<=1MiB。目录0700/文件0600，不额外加密。30秒检查点，退出有界冲刷；未知新schema不覆盖。清除包括内存、备份和截图，用代次拒绝旧结果。读取也拒绝过期。原AT-D04由本条细化。
- **AT-D10 可选v2面板**：保持API1/2兼容，以可选surfaces（默认dockPreview）声明panel，panel插件matches可用[*]；按插件身份从通用菜单入口装载，ctx.surface区分，panel的app/window为null，presentationID标识实例。panel输出用panel槽位，Dock不装载仅panel插件。共享VM与可见性租约，不互相挂起。旧宿主没有ctx.surface时插件返回空。日期起止分别以数字epoch动作传递，不引入任意对象动作。原apiVersion3仅候选，现采用可选v2增量。
- **AT-D11 分层授权**：记录开关、截图开关、系统录屏、插件activity.read、插件activity.snapshots独立；预装亦需明确批准两个新权限。不由插件启动采集，window.capture不授予后台留存。snapshots需同时获批read与snapshots；撤权/卸载/清除立即撤销引用与在途读取。截图默认只采用户明确选中的应用，另有密码管理器默认排除和用户排除项，不承诺自动识别全部隐身窗口。原AT-D06由本条细化。
- **AT-D12 有界API**：summary/sessions/snapshots均异步，查询[from,to)最长400天，时间值epoch秒；summary按查询IANA时区返回时间桶与应用，最多1000行，否则明确报错。sessions每页<=100，snapshots每页<=6，稳定游标绑定查询及revision，数据变化时拒绝旧游标（此判定被 AT-D26 的已读前缀规则取代）。响应<=1MiB。clear/撤权使在途结果失效。日期/分段/条形图/网格为有界声明式节点，仍遵守64节点/深度8；不在scene3d纹理中使用交互节点或活动引用。
- **AT-D13 截图新鲜性**：停留>=30秒首张，同应用跨session每10分钟最多一张；不从旧缓存取样。共享CG/SCK抓取及并发预算，采样时严格AX聚焦窗口身份+PID启动时间+windowID，前后核验前台/会话/授权；缺失即跳过，无整屏回退。只保存降采样小图，原图不入活动磁盘。活动ref由宿主解析，不向JS暴露像素或路径，禁止fs.read绕过读取Activity目录。
- **AT-D14 验证与状态**：先完成可执行的系统信号/状态机/存储和panel协议验证，再接生产入口；真实锁屏/睡眠/快速用户切换及macOS12/Intel不以模拟结果冒充。Preview/Worker注入纯夹具、无真实采集。M0已获推进授权；任务状态/实际命令/剩余限制另记实施验证台账。视觉核验为工程观察，不代替用户最终视觉批准。
- **AT-D15 设置归属与面板入口（2026-11-12）**：按用户实机反馈，活动记录、截图采样、保留期与排除名单集中到「偏好设置 → 插件」，不再放「通用」。插件选择器与独立插件面板均复用偏好设置的 `WindowCrystalModifier`、窗口背景结构及主题来源，禁止以透明窗口配无背景内容或仅叠低透明度填充。菜单栏按 manifest 的 `panel` 声明提供直接打开各插件面板的入口，活动时间线无需先经过选择器；仍保留通用选择器与原授权检查，不按插件 ID 添加业务分支。本条取代 AT-D10 中仅从通用入口打开的交互安排。
- **AT-D16 授权状态与活动图表（2026-11-12）**：采集开关不等于插件读取授权。活动插件默认关闭，首次启用须确认其声明权限，已有明确授权沿用。插件启用但有待确认权限时，设置卡片提供直接的「检查权限」操作，宿主活动采集选项归入声明 `activity.read` 的插件展开卡片；独立面板由宿主显示所需权限与确认入口，确认后才加载相应能力，不静默授权、不把缺少宿主能力误报为系统录屏权限。活动面板增加总时长、应用数量及按本地时间桶汇总的趋势折线／面积图，保留应用分布条形图和会话／截图。通用 `lineChart` 节点沿用有界 label/value 数据，最多 64 点，仅允许 panel，`ctx.uiFeatures.lineChart` 用于兼容回退；不传像素、路径或新数据类别。趋势按范围使用小时、日、月桶，按时间排序，合并各应用同桶时长；只在有保留数据且已发生的时间内补零，不外推未来或过期数据。趋势查询失败单独提示，不阻断已有排行和会话。
- **AT-D17 会话与截图纵向时间线（2026-11-12）**：会话与截图合并为一条由早到晚的纵向时间线，左侧显示日期和精确到秒的时间，中央使用连续轴线与节点，右侧显示应用、会话区间、时长和截图。`snapshots()` 增加可选的不透明 `sessionID`，对应已有会话 UUID；只有明确匹配当前会话页时才将截图归入会话，未匹配或旧宿主未返回关联时按截图时间单独排列，不根据应用名或时间猜测归属。现有会话页与截图页保持独立、有明确名称的分页，并说明时间线仅包含当前已载入的页。新增通用 `timeline` 节点 `{items:[{timestamp,content}]}`，最多 12 项，时间戳为非负有限 epoch 秒，内容沿用已有节点及整树 64 节点／深度 8 预算；仅允许 panel，禁止用于 scene3d 纹理，普通 panel fallback 沿用原规则。通过现有 `ctx.uiFeatures.timeline` 协商，旧宿主回退为同顺序的纵向内容列表。此条取代会话纯文字块与截图独立网格的展示安排；采集、授权、保留期及图片引用边界不变。
