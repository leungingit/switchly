# 插件独立预览开发任务书

日期：2026-11-03。依据：[插件独立预览与开发工具方案](plugin-preview-development-plan.md)。本文将方案拆为可分派、可独立审查的任务，不代表已经实施、通过验收或获得发布授权。当前全部任务为待开始；本次授权范围为任务文档编制。

**1. 交付目标与范围**

插件作者或 Agent 仅取得插件仓库、版本化 SDK/CLI 和预编译预览程序，即可在 Switchly 本体未运行时预览插件、执行动作、导出截图与报告。实现共享 JSC Runtime、解码器和原生渲染代码，默认使用合成系统能力。正式 Dock、AX、授权、跨屏及桌面玻璃验收仍由本体承担。

任务按 P0a 契约与可行性、P0b 可视 MVP、P1 可回归工具、P2 独立交付拆分。P0 不包含浏览器渲染器、市场、账户、完整 TS 构建链、MCP server 或正式宿主进程隔离改造。

所有新增文件名和目录均为规划路径；T02 冻结具体命名与接口后更新本任务书。既有实现、类型、预算和设置规则优先复用，不新增平行实现。具体插件源码、专属场景和算法留在 `../switchly-plugins`。

**2. 分工、文件所有权与交接规则**

| 工作包 | 建议责任人 | 主写入范围 | 边界 |
| --- | --- | --- | --- |
| 契约与集成 | 主控 | 本文、方案、契约说明、集成测试与正式台账 | 最终接口、架构和验收判断由主控负责 |
| 工程与构建 | 工程执行者 | `project.yml`、`Makefile`、新增工程脚本 | 统一处理所有 target/source/resource 接线；其他执行者仅提交接线需求 |
| 公共校验 | 契约执行者 | `plugin-api/`、CLI 校验模块、外仓校验接入 | 不修改 CLI dev/run 调度；保留外仓更严格资产策略 |
| Runtime 与 fixture | Runtime 执行者 | `Services/Plugins/` 必要注入点、预览 fake 与 worker | 不启动真实系统服务，不改正式宿主执行模式 |
| 原生渲染 | 原生执行者 | `Views/`、共享视觉实现必要修改、新增预览 GUI | 保持原生渲染与本体视觉契约一致 |
| 控制器与 CLI | 工具执行者 | 预览控制器、`packages/plugin-cli/` 的 dev/run 接入 | 不重复实现 Runtime、Schema 或渲染逻辑 |
| 插件场景 | 外仓执行者 | 外仓 `preview/`、fixture、专属测试与文档 | 不把插件业务写回宿主 |

规划中的预览专用 Swift 文件统一置于 `Tools/PluginPreview/`，按 `Worker/`、`Controller/`、`UI/`、`Fixtures/` 分写入范围；这不是另建一份 Runtime 或 Renderer。若 T01 证明需不同目录，由 T02 统一冻结。

并行规则：不同执行者不得同时修改同一文件。`project.yml`、`Makefile`、`PluginRuntime.swift`、`PluginOverlayView.swift`、`PluginSceneView.swift`、`cli.js` 和契约根文件由指定所有者串行集成；提取出的新文件可按工作包并行。外仓校验与 CLI 校验的公共样本由同一任务维护，避免两边各造一套。

每项交接必须包含任务编号、实际改动文件、接口版本、真实命令与结果、截图阅读结论（适用时）、剩余限制。任务完成不等于阶段通过，阶段门禁由主控复核。代码任务优先形成可独立审查的最小变更；提交、推送、发布仍按明确授权执行。

**4. P0a：先锁定可以独立开发的边界**

**T00 — 当前契约与依赖清点**

- 输入：现有方案、项目约定、公开 API、CLI、外仓 harness、Runtime、Renderer 与当前构建配置。
- 工作：清点最小源文件/类型/资源依赖；核对设置类型漂移、支持槽位、能力状态、现有测试与命令；列出允许复用和必须增加的注入点。
- 交付：在方案附录记录“源文件 → 依赖 → 所有者”及差异清单，不搬迁代码。
- 验收：每项结论有当前文件位置或真实检索证据；明确不引入 App 生命周期、SettingsService 或真实系统服务。未测平台单列。

**T01 — 独立原生窗口与截图可行性验证**

- 输入：T00 的最小依赖清单。
- 工作：用现有 Renderer 分别显示通用控件、Scene 和真实图片；验证 plain 截图与玻璃真实窗口路径，检查系统版本、GUI 会话和权限需求。
- 范围：由工程所有者接入最小探针 target；可保留并演进的源码进入正式预览目录，临时脚本、图片和日志放系统临时目录，不在仓库留调试残件。
- 交付：可运行探针、实际读过的截图、截图能力/系统降级矩阵及依赖结论。
- 验收：本体未运行时显示三类内容；图片与原生层没有静默缺失。无法截图的组合明确失败或不支持，不阻断可用路径。

**T02 — 冻结跨任务接口和支持矩阵（G0）**

- 输入：T00/T01 证据；冻结前不让多个执行者各自猜接口。
- 工作：定义场景/fixture/report 的版本、字段与错误语义；冻结 dev/run 参数、退出码、worker 消息、generation/requestID、共享渲染参数、能力/槽位支持表。
- 交付：契约说明、最小成功/失败样本、任务间接口表；T03 据此实现 Schema。兼容升级规则纳入说明。
- 验收：覆盖加载、渲染、动作、invalidate、暂停/恢复、卸载、错误、超时和关闭；明确 stdout/stderr 分工、帧/队列预算和重载 storage 策略。预算有来源，不能另造重复常量。
- 边界：场景业务 steps 在 P0 明确仅接受空数组；P1 新增步骤需向后兼容。不把文档中的计划项写成已发布能力。

**5. P0b：可视 MVP 的解耦任务**

**T03 — 公共校验收敛与场景 Schema**

- 范围：`plugin-api/`、公共 CLI 校验及外仓 `scripts/validate.mjs` 接入。
- 工作：实现 T02 场景/报告/fixture 约束与版本校验；外仓消费公共插件规则，保留资产和双语等更严格仓库策略；禁止 fixture 伪造 supported 状态。
- 交付：共享正反样本、可独立消费的校验制品、兼容性测试。
- 验收：`string` 等不支持设置按宿主契约拒绝；合法 toggle/select/number 一致通过；权限、路径、符号链接、体积和非法 JSON 在相应层拒绝。外仓独立演练用本地包制品，不依赖宿主源码路径。

**T04 — 正式预览 target 与共享源码接线**

- 范围：`project.yml`、`Makefile`、资源接线与必要构建脚本。
- 工作：将 T01 探针演进为 Preview App/worker 构建入口，复用正式 Runtime/Renderer/视觉实现的同一源码；控制依赖闭包，不先全面抽 Swift package。
- 交付：实际存在的构建命令、可运行产物、target 配置与资源归属检查。
- 验收：生成工程后检查差异；本体与预览均可构建；最低系统与降级明确，独立预览不装配 Dock/AX/真实媒体服务。新命令落地后同步本任务书，禁止先引用不存在的 Makefile 门禁。

**T05 — 合成能力与 Runtime 注入边界**

- 范围：Runtime 必要协议注入点与 `Tools/PluginPreview/Fixtures/`。
- 工作：复用已有媒体协议与 storage 接口；为 fs 增加最小 provider 边界；实现合成 media/weather/fs、设置和目标上下文，授予权限与 manifest 取交集。
- 交付：公共 fixture 加载器、状态容器、临时 storage seed/reset/dump、来源标记。
- 验收：首次 render 与基本 onAction 可使用三插件所需数据；缺权限/不可用/空值分别可测；不得触发真实网络、用户目录读取或媒体控制。正式 provider 行为与默认值保持原契约并有回归证据。

**T06 — JSC Worker 与内部消息协议**

- 范围：`Tools/PluginPreview/Worker/` 及共享协议编解码；不另写 JS 执行器。
- 工作：用真实 Runtime/解码执行 render/onAction，桥接 invalidate 与生命周期；实现长度前缀 UTF-8 JSON 帧、版本握手、请求串行化与消息预算。
- 交付：worker 二进制、协议测试、可供控制器使用的公共客户端接口。
- 验收：成功、JS 异常、无效 UI、非法/截断/超限帧、协议不兼容均有确定结果；日志只走 stderr；控制器能识别进程异常退出。输出编码不得通过另造 UI 模型绕过宿主解码。

**T07 — 会话控制器与进程监督**

- 范围：`Tools/PluginPreview/Controller/` 的会话与进程管理。
- 工作：装配 worker 与 GUI；管理启动/调用/关闭 watchdog、环境白名单、generation、队列背压、取消与清理；仅使用继承管道或当前用户本地 IPC。
- 交付：CLI/GUI 共用的会话接口与故障报告，不重复管理进程。
- 验收：死循环能被终止、必要时 kill 并 reap；窗口与 CLI 可退出；旧回调不覆盖新会话；没有无限恢复或重复 worker。关闭后无残留进程与监听。

**T08 — 共享渲染表面与原生预览窗口**

- 范围：共享槽位展示组件、`Tools/PluginPreview/UI/`、必要双语文案；依赖工程接线由 T04 所有者处理。
- 工作：复用 Overlay/Scene/资产/材质，提供主题、语言、玻璃、宽度、诊断和重载/重置入口；共享展示参数贯通本体与预览。P0 展示诊断状态即可，不另做复杂设计系统。
- 交付：原生窗口、共享渲染入口、截图导出接口，供 T09 消费。
- 验收：支持槽位与本体一致，未接入槽位明确提示；真实按钮/滑块/Scene hit 路由保留 pluginID；实际看过浅深色、语言、玻璃开关、长文案和边界宽度截图。窗口和内容背景共同检查透明度。

**T09 — CLI dev/run 与统一产物**

- 范围：CLI 命令模块与公共产物写入器；避免把全部逻辑堆入 `cli.js`。
- 工作：按 T02 接入控制器/GUI 接口；实现单次 run 和交互 dev，导出 report/PNG/声明式树/动作清单；CLI 参数与样本接口可先独立测试。
- 交付：`--json` 单一结果对象、stderr 日志、版本化 artifact 清单、退出码与环境诊断。
- 验收：真实联通由 T12 完成；本任务需验证参数、路径、报告一致性、失败非零与无 GUI 时的明确结果。既有 create/validate/build/verify 不回归；不自动更新锁、转译 TS 或下载工具。

**T10 — 整包热重载与生命周期联动**

- 范围：控制器 watcher、快照与会话切换；GUI 仅消费状态。
- 工作：合并文件事件、完整包复制/校验、成功后原子切换；资源缓存随 generation 更新；连接隐藏 suspend、显示 resume、关闭 unmount。
- 交付：重载状态机、stale 提示、显式重启/重置与 storage 策略实现。
- 验收：连续保存、写入中资产、加载失败、快速切换、隐藏后保存及关闭均覆盖；失败保留旧画面但 run 不计成功；旧 timer/invalidate/action 不进入新 VM；临时目录与 watcher 有停止路径。

**T11 — 三插件基础场景与外仓接入**

- 范围：只写 `../switchly-plugins` 的专属 fixture、preview 场景及测试说明。
- 工作：音乐覆盖空/播放/暂停/长标题/无封面；天气覆盖有/无天气、基础选择；鲸娘覆盖空会话/未读/忙碌；补充权限降级、语言及宽度边界场景。
- 交付：使用公共 Schema 的场景目录与本地工具调用示例，继续保留现有快速 Node 业务测试。
- 验收：场景不含真实用户数据和宿主源码引用；构建发行包不意外带入开发场景；`npm test`、`npm run build` 通过。真实预览在 T12 汇合验证。

**T12 — MVP 端到端集成验收（G1）**

- 工作：联通 CLI→控制器→worker→GUI，使用 T11 三插件场景；提供本地构建产物演练包，提前检查外部消费者路径。
- 验收：本体未运行时完成 dev 查看/操作/重载与 run 初始截图；通用控件、Scene、图片、错误、卡死和无 GUI 分支有证据；实际打开截图判断内容、边界和材质。截图权限限制分项报告。
- 门禁：执行适用构建/测试、共享源码本体回归及差异检查；记录冷启动、重载、静止资源和退出清理基线，不编造性能目标。
- 交付：MVP 验收记录、未验平台清单、P1/P2 修订估算。任何核心路径失败，G1 不通过，后续阶段不写成已交付。

**6. P1：可复现和可自动回归**

**T13 — 公共时间与随机源注入**

- 范围：同源 Runtime 与原生渲染的必要环境注入，按文件所有权串行集成。
- 工作：控制 JS Date/Math.random/Timer、Scene epoch/绘制时刻、hover、settle 和 marquee；正式默认实现继续使用系统来源。
- 交付：实时/固定/推进测试模式，以及时间边界和取消测试。
- 验收：相同 seed/输入/推进序列得到相同业务和动画采样结果；不会改系统时间/用户全局设置或插件源码；宿主默认行为回归通过。全链路未覆盖前不标记确定性完成。

**T14 — 场景步骤、业务动作和 trace**

- 范围：场景执行器、公共 steps 契约、报告与外仓业务步骤，Schema 改动经公共契约所有者集成。
- 工作：实现 action、时间推进、fixture 更新、状态/输出断言、trace 和有界稳定等待；保留 P0 空 steps 场景兼容。
- 交付：三插件操作场景、超时/歧义/禁用动作错误、来源可追溯报告。
- 验收：音乐播放/暂停、天气选择/揭示/结束、鲸娘状态变化可重放；直接 onAction 调用明确标为业务动作测试。失败定位到步骤，旧 generation 不能继续执行。

**T15 — 原生输入与可达性回归**

- 范围：原生测试驱动及通用控件/Scene 输入测试。
- 工作：验证点击、滑块、hover、disabled、键盘与可访问标签，覆盖 Scene hit region；不以声明式树冒充 AX 树。
- 交付：与 T14 业务动作测试分开的原生输入结果与截图证据。
- 验收：证明操作确实经过原生输入路径；禁用控件不触发业务，缩放后命中区域正确，键盘与焦点可见。受环境或授权阻碍的用例明确未验，不用直接调用替代通过。

**T16 — 视觉基线与差异报告**

- 范围：截图比较器、环境指纹与基线管理；正式基线按项目约定保存，调试图片在临时目录。
