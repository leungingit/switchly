# Switchly 界面工程约束

本文约束 SwiftUI / AppKit 界面的实现和验收，与 [设计系统](design-system.md) 及根目录 [AGENTS.md](../AGENTS.md) 配套。Switchly 是本地原生 macOS 应用；这里的界面约束不引入 Web 前后端或网页响应式框架。

## 实现边界

1. Views 处理展示、输入和面板自身生命周期；业务状态交由 ViewModel，持久化、窗口枚举、AX 操作和截图交由 Service。复用现有协议、设置与窗口匹配规则。
2. UI 状态与 AppKit 窗口操作在主线程执行。关闭面板、切换目标或停止服务时，取消异步任务、刷新兴趣、订阅和事件监听；返回旧结果前核对目标及取消状态。
3. 外观参数贯通 `AppSettings`、兼容解码、`SettingsService`、变更通知和实际消费方。共享设置不另建重复开关；保存后验证已打开及新打开的面板，而非只检查设置页读数。
4. 复用共享令牌、材质和主题应用。新增共用数值放到对应共享文件，不在 View 中复制同用途公式。现有局部数值仅在任务涉及时收敛。
5. 文案同时维护英文和简体中文；错误文案描述用户可采取的动作，系统返回码等细节留在本地日志。

## 窗口与布局

- 依据目标屏幕 `visibleFrame` 约束尺寸和位置，覆盖副屏、混合缩放、全屏空间和 Dock 方向变化；不能套用网页 375 / 768 / 1440 断点作为原生验收依据。
- 同时检查 NSWindow / NSPanel 背景与 SwiftUI 内容层。窗口透明但内容实心、四角方块、重复模糊或越界高光都算缺陷。
- 容器布局服从各自功能。Dock 保持应用窗口入口，偏好设置保持表单，工作区管理保持编辑结构，统计保持图表；不因复用材质而强制采用主预览舞台布局。
- 覆盖长标题、多窗口、空状态、加载、权限缺失、窗口关闭和内容溢出。截断不应掩盖关键操作；内容过多时采用合适的滚动和屏幕边界约束。
- 方向键移动、列数和画面排列一致；提供可理解的标签、键盘路径与焦点反馈。不能只用颜色表达选中、错误或结果。

## 材质和性能

- 背景模糊以面板 / 普通窗口为所有者；卡片只叠纯 SwiftUI 表面，不各自新建模糊视图。统计和设置窗口仍拥有自己的背景，不依赖另一个窗口的材质实例。
- `enableBackgroundBlur`、`.clear` 无面板、wash、染色、柔光与镜面强度分别有真实语义；零值及极值必须影响对应实际渲染层。
- 缩略图和放大预览复用现有缓存与刷新预算，避免 UI 为视觉效果重复截图。拖动滑块不应触发无边界采样或高开销同步操作。
- 材质示意的背景来源与限制必须说明。示意复用当前设置窗口背景时，不把它当成独立面板背景强度的实测证据。
- 新系统 API 有可用性检查和 macOS 12 降级。动画尊重系统减少动态效果，避免每个控件自建重复无限动画。

## 验收与证据标准

Swift 改动先执行 `make build` 和 `make test-unit`，再按风险验证实际场景。`GlassAppearanceTests` 覆盖表面系数、零值、普通窗口背景所有权和背景视图更新；`AppSettingsTests` 覆盖兼容设置。测试通过不能替代系统合成与视觉证据。

| 验收维度 | 至少检查 |
| --- | --- |
| 主题与材质 | 浅色、深色、跟随系统；模糊开 / 关；玻璃 / 无面板；wash、染色、柔光和镜面边的零值及代表性中高值。 |
| 布局 | 舞台与网格的真实差异、列数及键盘导航；相关窗口的边界、间距、遮挡和滚动。 |
| 可读性 | 文字、次要信息、图表、焦点与选中态；以实际合成表面测量普通文字至少 4.5:1 的对比度目标，不能套用历史固定背景数值。 |
| 桌面透射 | 浅色、深色及彩色壁纸下的模糊、色相、唇边和灰边；无双重模糊或高光过曝。 |
| Dock | 不同图标之间移动、启用 Dock 放大、贴靠间距及屏幕边界；无错位、闪烁或遮挡。 |
| 多屏 | 副屏、不同缩放比例及全屏应用上的定位、圆角、边界和窗口切换。 |
| 设置 | 保存后即时生效、重启后保持、旧数据不丢失；材质和布局选项都产生可观察的结果。 |
| 生命周期 | 反复开关预览 50 次后观察内存 / GPU 是否回落、刷新兴趣和监听是否释放；记录具体条件，不能仅凭次数报告性能通过。 |

实际运行时确认 bundle 路径、签名及版本，避免混测 Debug、Release、`build/` 或「应用程序」中的不同副本。截图使用可公开演示内容，不暴露工作窗口的私人信息。

离屏 `NSHostingView` 渲染可检查布局和部分配色，但 `NSVisualEffectView` 可能无法重现桌面合成。HTML 原型、功能插画和源码渲染必须标明来源，不能冒充真实产品截图。真实 UI 改动交付必须查看运行截图；无法取得时明确列出未验项，不报告视觉通过。

## 当前证据与后续回归

迁移前的设计 QA 主要依据原生源码离屏渲染；真实壁纸透射、Dock 贴靠、多显示器与全屏空间、反复开关的资源占用仍需真实桌面证据。历史三预设的 RGB / 对比度测量与旧参数绑定，不代表当前任意自定义材质都达标。

仓库保留的 [偏好设置源码渲染图](images/preferences-source-render.png) 仅供了解布局；README 主图和功能图是插画。此次文档迁移不新增视觉或系统行为验收结论。

根目录 `work/` 仅用于本地临时排障与过程文件，已加入 Git 忽略，不提交。新的临时截图、脚本和日志优先放系统临时目录的任务子目录。设计过程文件完成必要知识迁移后可以清理；正式规范、测试夹具和被文档引用的图片放在可追踪目录，避免依赖已删除的工作目录。
