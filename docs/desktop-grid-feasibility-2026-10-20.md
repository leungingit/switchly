# 桌面网格第一轮可行性研究

日期：2026-10-20。对应 [候选功能与交互方案](desktop-grid-research-and-spec.md)。本轮完成上游实现核验、仓库适配核查及本机只读探测，未实现产品功能，未切换、创建、删除桌面或移动用户窗口。

## 1. 决策

**有条件可行，建议进入有退出条件的技术原型；目前不足以批准完整产品开发或宣布 macOS 12+ 全面支持。**

- 可继续：在原生 Spaces 上建立二维索引、别名、方向选择与图标总览。本机已经取得多个屏幕的桌面列表、会话内标识和当前桌面；已有架构可承接。
- 必须先验证：空桌面直达、系统重排后的身份跟踪、跨桌面窗口归属完整性。这是核心导航功能的前置条件，不能用漂亮的网格替代。
- 单独验证后开放：单窗口移动、移动并跟随、全屏/最小化行为。窗口移动失败不阻断基础导航立项，但需要缩减承诺。
- 首版保留系统操作：创建、删除桌面和 Dock 应用分配，Switchly 提供指引与结果同步。
- 不采用：改变系统为真正二维 Spaces、接管系统动画、要求关闭 SIP、注入 Dock、自建离屏工作区、九路实时桌面捕获。

如果要求“纯公开 API、完整控制原生 Spaces、兼容全部 macOS 12+、可上 Mac App Store”同时成立，当前计划不可直接成立。应先确定分发路线与系统能力边界。

## 3. 本机只读探测

### 3.1 环境与方法

本机命令实际报告：`macOS 27.0.1 (26A434)`、`arm64`、SIP enabled；按原样记录，未将其推定为 macOS 26 的兼容测试。Xcode 路径为 `/Applications/Xcode.app/Contents/Developer`。

探针：[`space-readonly-probe.m`](research/desktop-grid/space-readonly-probe.m)。动态加载系统 SkyLight，调用：

- `SLSCopyManagedDisplaySpaces`：读取显示器与桌面快照；
- `SLSManagedDisplayGetCurrentSpace`：逐显示器读取当前桌面；
- `SLSCopySpacesForWindows`：对 CoreGraphics 返回的 layer 0 项逐个查询归属。

另外执行不弹窗的 AX/截图权限预检；只检查窗口移动相关导出符号及 Objective-C 类是否存在，**不调用写接口**。不输出应用名、窗口标题、内容或显示器 UUID；会输出临时 Space ID。原始 JSON 留在系统临时目录，不加入仓库。

分别运行普通编译产物，以及相同源码的 ad-hoc 签名、启用 hardened runtime、无额外 entitlements 的独立产物。签名只施加于临时探针，没有改变 Switchly 签名或系统权限。

### 3.2 结果

| 检查 | 普通产物 | Hardened runtime 产物 | 能说明什么 |
| --- | --- | --- | --- |
| 桌面结构 | 2 个显示器，分别 2 / 4 个 Space，共 6 个 | 一致 | 读取原生多屏结构的路径在本机可工作 |
| Space 类型与 UUID 字段 | 6 个均 type 0，均有 UUID 字段 | 一致 | 可取得普通桌面身份线索；没有实测全屏类型 |
| 当前桌面 | 两屏均在各自列表中找到 | 一致 | 可取得逐屏当前值；尚未与用户目视逐一核对 |
| 连续枚举 | 100/100 有结果，100/100 等于初始快照 | 一致 | 静止场景短时重复读取一致；不是切换成功率 |
| 枚举耗时 P50 / P95 / 最大 | 0.043 / 0.058 / 0.120 ms | 0.050 / 0.079 / 2.494 ms | 仅同步快照调用微基准，不是 UI 首帧或切换耗时 |
| layer 0 项归属查询 | 286 项中 36 项非空，250 项为空，0 个 null | 一致 | 存在可用归属；完整性尚未建立 |
| 非空结果检查 | 3 项归属均不包含任一显示器的当前 Space；0 个未知 Space ID | 一致 | 能返回跨当前桌面的归属线索 |
| 单批归属查询耗时 | 9.340 ms | 8.193 ms | 仅当前样本；没有测 AX 匹配、筛选或截图 |
| 权限预检 | AX trusted；Screen Capture false | 一致 | 探针执行上下文状态，不能代替 Switchly bundle 授权判断 |
| 写操作线索 | 旧移动导出符号与 bridged move 类均存在 | 一致 | 仅存在性，不证明移动可用 |

286 项是 CG 返回的 layer 0 项，**不是经过 AX 匹配确认的 286 个用户窗口**。250 个空归属不能直接解释成“不属于任何桌面”，也不能作为成功覆盖率或系统 bug；可能包含不应展示的窗口对象等情况，须用受控窗口样本进一步归因。36 项也不能直接视为用户真实窗口清单。“不包含任一显示器的当前 Space”按所有显示器当前 ID 的集合判断，不是按每个窗口所在显示器判断，不能当作逐显示器离屏窗口计数。

本轮未改显示器配置，`spans-displays` 偏好键未显式存在，因此不依据缺失键推定独立 Spaces 开关。读取到的双屏结构不能替代开/关两种模式测试。

100 次枚举为同进程紧密循环，未施加桌面变化，没有采集 WindowServer CPU、swap、GPU 或能耗。因此不能用上述微秒级读取成绩宣布“九桌面无性能问题”。

### 3.3 可复现命令

以下复现测量流程，不保证复现相同样本数量、权限状态或耗时。请从仓库根目录执行；所有二进制及 JSON 写入新建的临时目录：

```sh
probe_dir=$(mktemp -d /tmp/switchly-grid-probe.XXXXXX)
xcrun clang -fobjc-arc -Wall -Wextra -Werror \
  -framework Foundation -framework ApplicationServices \
  docs/research/desktop-grid/space-readonly-probe.m -o "$probe_dir/probe"
"$probe_dir/probe" > "$probe_dir/result.json"
cp "$probe_dir/probe" "$probe_dir/probe-hardened"
codesign --force --sign - --options runtime "$probe_dir/probe-hardened"
"$probe_dir/probe-hardened" > "$probe_dir/result-hardened.json"
cat "$probe_dir/result.json" "$probe_dir/result-hardened.json"
```

探针不申请新权限、不发快捷键或手势、不操作任何窗口。非公开接口可能随系统改变而失效；出错应停止并记录，不循环重试。探针没有加入 app 编译目标，不是生产服务实现。

## 4. 原计划需要修正的技术认识

### 4.1 切换桌面：有实现先例，尚未验证本机

[yabai 变更记录](https://github.com/asmvik/yabai/blob/dd845723416f5fe92af49fad5ebab00369e07edd/CHANGELOG.md)记录 7.1.19 加入 SIP 开启时的聚焦能力。固定提交 [space_manager.c](https://github.com/asmvik/yabai/blob/dd845723416f5fe92af49fad5ebab00369e07edd/src/space_manager.c) 中 `space_manager_focus_space_using_gesture` 用非公开 CGEvent 字段构造高速度横向手势，按当前位置与目标位置差重复提交。

推论：它支持“逻辑二维选择，底层横向执行”的候选路线；不是系统提供的二维切换 API，也不是一次任意 Space ID 原子跳转。动画状态、快速连发、多屏光标位置与系统设置都会影响实际行为，需要目标确认与有限超时。上游函数返回成功也不能代替实际当前 Space 检查。

验证顺序应比较：已启用的系统桌面直达快捷键 → 原生相邻切换 → 非公开手势路径。不能偷偷更改用户快捷键，也不能默认每个桌面都已配置直达键。只有手势路径被证明必要且可靠时才接入；若只能顺序跳转，需实测是否仍改善总耗时。

### 4.2 移动窗口：比原计划表述更复杂

同一提交的 `space_manager_move_window_to_space` 包含三类路径：bridged operation、旧 `SLSMoveWindowsToManagedSpace`、受限情况下的其他回退。更关键的是，[yabai.c 初始化](https://github.com/asmvik/yabai/blob/dd845723416f5fe92af49fad5ebab00369e07edd/src/yabai.c#L148-L149) 使用 Mach-O 符号查找取得内部函数，并非只靠普通 `dlsym` 导出查找。

因此，普通 `dlsym("SLSPerformAsynchronousBridgedWindowManagementOperation")` 找不到该名字，不能据此判定能力不存在；找到了 bridged move 类也不能证明能完成调用。不要将本轮存在性检查升级成移动支持声明，也不要未经测量直接把读取内部符号的复杂实现搬入 Switchly。

需要评估是否可用足够简单、可确认结果的路径完成普通窗口移动；若必须维护 Mach-O/系统内部布局解析才能支持目标系统，窗口拖放应独立延期并重新评估维护收益。

### 4.3 创建/删除与身份

上游创建/删除仍依赖 scripting addition，不能自然推导为“读取接口能用，所以创建也能用”。本轮维持系统 Mission Control 指引方案，无需为首版引入注入或降低 SIP。

已读到 Space UUID 字段，只支持会话内映射的进一步实验。跨 Dock 重启、系统重启、重排、插拔屏幕的身份稳定性尚未证实。持久化设计必须能将不确定映射标为待绑定，禁止仅凭序号把旧别名套到新桌面。

### 4.4 分发与许可证

[Apple App Review Guidelines 2.5.1](https://developer.apple.com/app-store/review/guidelines/#software-requirements)要求使用公开 API。依赖非公开 Spaces 接口的路线与该要求冲突，应以现有站外分发路线评估，不能承诺 Mac App Store 上架。Developer ID 签名、公证及安装后的 TCC 行为仍需最终 app 实测；本轮临时 hardened runtime 探针不是公证验证。

上游 [LICENSE.txt](https://github.com/asmvik/yabai/blob/dd845723416f5fe92af49fad5ebab00369e07edd/LICENSE.txt) 为 MIT，允许在遵守其通知保留条件下参考和复用。许可证可接受不代表系统接口稳定。本轮仅按接口签名编写独立只读探针，没有引入 yabai 依赖或复制其控制实现。

## 5. 与现有 Switchly 的适配

| 现有设施 | 代码证据 | 适配判断 |
| --- | --- | --- |
| Workspace 应用分组 | `Models/Workspace.swift:10–33`；`README.md` 的 Workspaces 说明 | 保留原语义；不能当作真实 Space 数据层 |
| 当前可见窗口 | `Services/WindowMonitorService.swift:121–160` | 基于屏幕可见 CG 列表，当前路径将标志设 true；需另建 Space 成员关系 |
| 窗口模型 | `Models/WindowInfo.swift:17` | `isOnCurrentSpace` 不足以表达多屏及多 Space 归属；采用独立归属快照与既有窗口匹配 |
| 设置 | `Services/SettingsService.swift:10–19,46–75` | 复用持久化、旧键兼容、缓存与通知；新字段用默认值解码 |
| 缩略图 | `Services/ThumbnailService.swift` 的 owner 刷新与缓存路径 | 复用捕获预算；先做图标版，不因离屏无图阻止导航 |
| 签名与工程 | `project.yml` 的 hardened runtime 与空 entitlements | 生产服务仍需在真实 bundle 验证，不新增 sandbox 或不必要权限 |

建议将系统能力封装在 `NativeSpacesServiceProtocol` 后，单独维护 `SpaceSnapshot` / `DesktopGridMapping`；上层 ViewModel 使用能力标志与失败原因。私有 API 签名、系统版本判断和回退集中到同一服务后端，不分散在 View、快捷键或现有 Workspace 中。

刷新由系统变更、面板生命周期与明确用户操作驱动，合并重复通知；关闭面板取消网格自己的订阅及捕获兴趣。现有截图服务与窗口列表服务继续承担原职责。

## 6. 性能可行性判断

**没有发现“读取 4–9 个 Space 元数据必然不可承受”的证据；主要风险仍是应用负载、图像与系统控制路径。** 本机已有总计 6 个 Space，但这是跨两屏 2+4，不能等价于单屏 6 或 9 桌面测试。

本轮只测元数据读取。9 张 640×400 RGBA 单份像素约 8.79 MiB 的估算仍成立，但未包含多窗口、缓冲、纹理和捕获源图。建议原型先仅用图标和文字，控制变量证明系统操作成立后再加缓存图。

完整性能验证沿用原方案第 4.4 节：固定应用/窗口负载，对照 1/4/6/9 桌面，测 Switchly 与 WindowServer、内存压力与 swap、切换 P50/P95；关闭面板后网格新增截图为零。不能拿本轮同步读取 P95 代替此实验。

以下是后续原型的执行拆分，尚未全部执行。先做 R1–R3，再决定是否投入完整 UI；R4 是增强能力独立门槛。

| 编号 | 任务与具体交付 | 依赖 | 建议模型/方式 | 完成标准与停止条件 |
| --- | --- | --- | --- | --- |
| R0 | 本轮资料、架构与只读探针 | 无 | 简单核查用低费模型，主任务验证 | 已完成，证据如上 |
| R1 | 受控窗口夹具；核对普通/全屏/最小化/跨桌面归属；解释空结果 | R0 | 低费模型整理夹具清单；主任务编写/审查系统探针并实测 | 已知窗口归属可与系统操作前后对应；不猜测空结果；无法建正确集合则先删窗口预览范围 |

R1 与 R2 的准备工作可并行，但**实际改变桌面/焦点/窗口的测试必须串行**，避免不同 Agent 互相污染状态。改变桌面数量、Dock、显示器或系统开关时，采用可恢复测试场景，并事先说明会短暂影响当前操作环境；不得对不确定的原始布局强行恢复。

建议为 R1–R3 设一个短期技术验证预算，首次以 2–3 个工作日为排期假设，按可获得的测试机器校准；这不是兼容全系统的工期承诺。若预算内核心导航仍不可靠，先停止 UI 投入，保留证据并重新决策。无法取得旧版 macOS/Intel 测试机时应收窄新功能支持范围，现有产品最低系统不必随新功能一起提高。

## 8. 决策门槛与本轮限制

| 门槛 | 当前判断 | 影响 |
| --- | --- | --- |
| 本机读原生桌面结构、会话内当前值 | 小规模探针通过 | 可以进入受控原型 |
| 同一进程静止场景读取开销 | 微基准通过，无明显成本信号 | 不代表九宫格整体性能验收 |
| 稳定身份与跨生命周期映射 | 未验证 | 固定位置导航未获最终放行 |
| 空桌面/远距离/多屏切换及结果确认 | 未执行 | 核心导航未获最终放行 |
| 完整窗口索引与移动 | 部分读取线索；写入未执行 | 不能承诺窗口拖放、批量 app 移动 |
| 自动创建/删除 | 本轮不采用 | 首版系统引导可保留 |
| 分发 | 可沿现有站外方向继续评估 | 公证未验证；不承诺 App Store |
| 4–9 桌面真实性能与用户收益 | 未验证 | 不宣称性能或效率达标 |

本轮完整完成的是“研究与非侵入式探测”，不是原方案阶段 A 全部系统实验。没有申请屏幕录制权限，没有捕获桌面图，没有中断正在运行的 Switchly，没有改变桌面或窗口，也没有进行用户访谈。应用代码未改，未运行 `make build` / `make test-unit`；独立探针已通过严格 clang 编译并实际执行普通/加固签名两种产物。

据现有证据，可以明确投入下一轮核心控制原型；不能把“有条件可行”写成完整开发已获技术验收。下一轮的首要交付应是 R1–R3 的结果表和继续/缩减/停止决策，而不是先完成九宫格界面。
