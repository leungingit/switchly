# 缩略图跨次启动复用

## 目标与范围

Switchly 重启后，仍在运行的目标应用窗口可以先显示此前成功捕获的小尺寸缩略图，再后台获取新图。仅增加本地缓存，不新增网络、依赖或设置项。

首次使用本功能时没有旧版本遗留图片可迁移，必须先成功截图一次。目标应用退出重开、系统重启、窗口身份或标题变化后，不按相似标题猜测复用。

## 缓存契约

| 项目 | 规则 |
| --- | --- |
| 位置 | `~/Library/Caches/Switchly/Thumbnails/` |
| 有效期 | 从原始截图时间起 24 小时；读取、恢复和刷新失败均不延长 |
| 磁盘预算 | 图片和元数据合计 64 MB，最多 200 个文件，最旧优先淘汰 |
| 图片规格 | 仅 grid 层级压缩 JPEG，小图最长边不超过 1200 像素；native 放大图不落盘 |
| 窗口身份 | 系统启动会话、目标应用路径、PID、进程启动时间、窗口 ID 与标题组合的 SHA-256 摘要 |
| 文件内容 | 格式版本、身份摘要、原始截图时间、像素尺寸、缩放比例与图片数据；不保存明文标题或应用路径 |
| 读写方式 | 专用后台串行队列，图片编解码和目录扫描不阻塞主线程，文件原子替换 |
| 访问权限 | 目录 0700，文件 0600；本地图片未额外加密，可手动删除目录 |
| 过期清理 | 启动及写入时批量清理；读取时拒绝并删除过期文件；退出期间过期的文件下次启动清理 |
| 权限降级 | 没有录屏权限时不从磁盘恢复图片；缓存缺失、损坏或身份不可确认时沿用截图与图标降级流程 |
| 退出收尾 | 最多等待 0.5 秒，处理已经入队的写入；不等待未完成的系统截图 |

## 与现有服务的衔接

`ThumbnailDiskCache` 实现可注入的 `ThumbnailDiskCaching` 协议。生产单例启用磁盘缓存，原有单元测试默认不接触真实缓存目录。

`getCachedThumbnail` 保持同步的纯内存读取，避免在 SwiftUI 初始化与 body 路径读盘。grid 图片可在 24 小时内作为旧图占位，原有约 45 秒的新鲜度阈值继续控制后台刷新；native 层级仍保持原有 60 秒有效期。

按需获取图片时先异步尝试恢复磁盘图，恢复过程不等待正在进行的系统截图。预热捕获也会先发布可用旧图。新图成功时替换内存和磁盘缓存；失败时保留仍有效的旧图及原有失败退避。Dock 和普通预览卡片不再在读盘之前因失败冷却而提前返回。

较慢的旧图读取不能覆盖刚完成的新截图，较旧的异步写入不能覆盖新文件。缓存条目分别保留拥有者和标题，防止共享元数据更新导致不同层级之间串图。内存清理或淘汰不会解除仍在进行的截图任务占用。

## 验证

自动化测试使用临时目录和生成的图片，不需要截图用户窗口。覆盖新实例恢复、真实进程身份解析、目标应用重开与系统重启隔离、24 小时过期、读取不续期、预算淘汰、损坏文件、权限、最长边限制、乱序写入、退出写入收尾，以及服务层的失败兜底、并发截图、取消和慢读覆盖保护。

执行：`make generate`、`make build`、`make test-unit`、`make build-release`、`git diff --check`。

本次完整单元测试 246 项通过、0 失败；其中新增 25 项缓存与窗口身份回归测试。Debug 和 Release 构建均通过。现有 CoreSimulator 版本提示不影响本次 macOS 构建与单元测试。

系统捕获与实际 Dock 展示仍需在有录屏权限的真实运行实例中验证，不能用临时目录测试替代。验收时应使用同一构建产物：成功预览一个窗口，退出并重开 Switchly，确认该目标进程仍在运行、未更改标题时可恢复旧图，再检查后台更新；目标应用退出重开后不应复用旧进程图片。
