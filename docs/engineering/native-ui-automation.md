# Switchly 原生界面自动化操作规范

## AUTO-D01 — 自行打开偏好设置并截图核验（2026-11-12）

用户已明确要求：以后由 Agent 自行打开 **Switchly App 自身的偏好设置**并截图核验，不再默认要求用户人工打开。此规则适用于任务所需的打开／聚焦窗口、页面导航与截图查看；设置值修改、系统授权与真实活动采集仍遵循任务授权和现有隐私约束。

### 操作路径与验证目标

1. 确认目标应用的完整路径及运行 PID，避免混用工作区、Xcode DerivedData、下载目录或分发副本。工作区 Debug 默认路径为 `<仓库绝对路径>/DerivedData/Build/Products/Debug/Switchly.app`；其他检出目录须使用各自路径，不硬编码本机用户名。
2. 通过当前环境的原生电脑操作工具连接该完整路径。浏览器不能直接控制 AppKit 窗口，不能以浏览器无法访问为由把操作交给用户。
3. 读取最新无障碍控件树，打开应用菜单 `Switchly`，重新读取菜单状态，点击实际出现的 `Settings…` 项。该入口发送 `.openPreferences`，由 `AppDelegate.openPreferences` 创建或聚焦自定义窗口；无需新增调试接口或修改偏好文件。
4. 确认返回窗口为 `Switchly 偏好设置`（英文为 `Switchly Preferences`），并有通用、外观、应用、桌面网格、权限、插件、快捷键等分类。按任务进入目标页，每次操作后重新读取控件树，使用本次返回的元素索引。
5. 获取目标窗口截图并实际查看，确认非空白、标题和目标页正确，检查文字、控件、裁切、重叠及所涉及的材质。控件树或截图调用成功均不能单独代替看图核验。

可用以下只读命令辅助核对运行副本；没有匹配进程时 `pgrep` 返回非零，不等于工具权限不足：

```sh
pgrep -fl '^.*/Switchly.app/Contents/MacOS/Switchly$'
```

### 当前会话已验证的工具用法

本次通过 `mcp__cua_repl.js` 的原生 `cua` API 完成。工具 API 以会话返回文档为准，分次执行并根据最新控件树选择元素，不照抄历史数字索引。

```javascript
// 将占位路径替换为本次检出的真实绝对路径。
var switchly = await cua.getApp("<仓库绝对路径>/DerivedData/Build/Products/Debug/Switchly.app");
```

连接返回最新控件树后，分别执行以下步骤；`menuIndex` 与 `settingsIndex` 必须从对应步骤的实际返回值取得：

```javascript
// 从连接结果找到菜单栏中的 Switchly。
await switchly.click(menuIndex);
await switchly.getAXState();
```

```javascript
// 从刚返回的菜单中找到 Settings…。
await switchly.click(settingsIndex);
await switchly.getAXStateAndScreenshot();
```

`getAXStateAndScreenshot()` 会直接展示控件树和图片，Agent 必须查看图片。若当前工具要求结束时发送操作完成摘要，按工具约定发送。截图若需落盘，存放系统临时目录的任务子目录，核验后清理；不为本规范另建截图或自动化脚本到工作区。

### 失败定位与人工介入边界

| 现象 | Agent 应执行的下一步 | 不可据此作出的判断 |
| --- | --- | --- |
| `Ambiguous app identifier` | 使用目标应用完整路径，核对所有运行副本 | “Switchly 必须由用户手动打开” |
| `timeoutReached` | 核对目标路径、PID 是否变化和多副本状态；必要时用 Finder 等无关原生应用的只读控件树区分目标应用故障与工具整体故障，再依据新信息重试 | 未取得证据就归因锁屏、权限或多副本；无变化地反复重试 |
| 进程退出、重启或路径变化 | 重新识别目标；避免验收期间构建、重签同一运行副本；不擅自退出其他任务或用户的实例 | 将不同进程的状态与截图拼成同一实例的验证结论 |
| 返回白图或不包含 sheet | 区分父窗口与弹窗捕获，使用当前允许的捕获方式取得包含目标层的有效图片并查看 | “控件存在，所以视觉通过”；“一次白图，所以用户必须代截图” |
| Switchly 内部“权限”页提示缺少屏幕录制 | 分别核对 Switchly 的捕获权限和电脑操作工具的实际结果 | 将 Switchly 自身缺少录屏权限等同于无法打开其偏好设置或无法截取设置窗口 |
| 已证实锁屏、所需权限缺失或原生工具不可用，且授权范围内的替代路径仍不可行 | 说明具体步骤、原始错误和尝试结果，只请求解锁、所需授权等最小必要协助；恢复后 Agent 接手后续操作 | 未尝试工具就要求用户完成整个打开、导航、截图流程 |

Switchly 内部“权限”页仍属于 App 自身偏好设置。打开 macOS 系统设置不属于完成本路径的必要步骤；不要为打开或截图核验而额外改变系统权限、真实记录开关或截图允许列表。

### 本次实测依据与结论范围

2026-11-12 当前对话的真实操作记录：

- 按名称及完整路径连接曾返回 `Computer Use server error -10005: timeoutReached`；同阶段 Finder 控件树可读取。
- 按 `com.switchly.app` 连接明确返回 `Ambiguous app identifier`，提示存在多个同 Bundle ID 的应用路径；只读进程检查曾发现两个不同路径的运行副本，随后 PID 发生变化，非本次 Agent 主动退出或重启。
- 后续通过工作区完整路径连接成功，返回 `Window: "Switchly 偏好设置", App: Switchly.`；通过原生菜单点击 `Settings…` 后再次返回该窗口及有效截图。实际看图确认分类栏、权限说明与按钮完整可见，未见裁切或重叠。
- 该图显示 Switchly 自身辅助功能启用、屏幕录制仍有“必需”提示，但此次设置窗口截图成功；没有点击“打开设置”、修改权限或开启采集。

本轮证实了已有运行实例的连接、设置菜单触发、偏好窗口聚焦和截图查看可行；未单独证明从关闭窗口或未运行进程开始的冷启动流程。最初超时的底层根因尚未完全查明，不能把多副本或 PID 变化直接写成超时的唯一原因。Finder 曾返回白图，也不代表所有窗口截图均失败。上述阶段记录不保证未来工具、系统权限或应用版本始终不变，后续仍以当次真实结果为准。

**问题 → 方案 → 后续**：默认交给用户打开偏好设置 → Agent 按固定路径、原生菜单、最新控件树、有效截图自行完成 → 后续遇到阻塞先取证定位，仅在证实无法自行推进时请求最小人工协助。


## AUTO-D02 — 无可见窗口时使用标准再次打开事件（2026-11-12）

菜单栏应用无可见窗口时，原生工具和 XCUITest 对应用菜单可能分别返回 `timeoutReached` 和零尺寸 `not hittable`。宿主通过标准 `applicationShouldHandleReopen` 处理再次打开：已有进程且没有可见窗口时显示偏好设置；初次启动仍保持菜单栏应用行为。可先核对唯一副本，再对同一完整 App 路径使用系统 `open`；它不是调试参数或权限旁路。本轮已实测：停止旧副本并构建后，按完整路径启动，再对同一路径执行一次 `open`，原生工具返回完整「Switchly 偏好设置」窗口；未请求用户代开。此结果仅覆盖本机当前 macOS／arm64。


## AUTO-D03 — 菜单索引失效时重新绑定（2026-11-12）

原生应用菜单展开后，若最新树中的菜单项仍返回 `The element ID is no longer valid`，不要重复点击旧 ID，也不要据此认定产品菜单失效。对相同完整路径重新 `cua.getApp`，读取连接结果中的菜单索引后再点击。本轮以此成功点击 `Settings…` 并聚焦已有插件设置窗口；键名 `comma` 可以被键盘接口识别，字面量逗号会返回 `keyNotFound`，快捷键尝试本身不能代替窗口结果核验。

## AUTO-D04 — 独立插件面板按标准窗口定位（2026-11-13）

本轮实机中，原 `NSPanel` 选择器／活动面板未出现在系统 `Window` 菜单中；工具重新读取状态时会回到偏好设置。按 AT-D19 改为标准 `NSWindow` 后，已实测菜单同时列出「Switchly 偏好设置」「插件面板」「活动时间线」，选择活动时间线后返回其标准窗口与真实数据。

同一应用有多个窗口时，先读取最新控件树，通过 `Window` 菜单中的真实窗口名称选择目标，再读取新状态；不要把其他窗口的索引带到当前窗口。捕获证据优先使用同一次 `getAXStateAndScreenshot` 返回的状态和图片，避免分别读取时混配窗口。若菜单处于展开状态，先操作当前菜单或执行其已暴露的取消动作，不能把菜单索引当作内容控件。

独立窗口的原生标题栏与滚动内容分开，使用系统语义背景；边界以最终窗口框架为准，不能只约束内容矩形而漏算标题栏高度。该约定不改变 Dock 浮层或隐藏预览，不替代状态栏入口的真实点击证据。

## AUTO-D05 — 清除确认只在隔离库验收（2026-11-13）

按 AT-D22，禁止对真实活动库打开清除确认来补截图，即便计划只观察空输入和取消。本轮首次观察可返回 sheet 和有效截图，紧接着再次观察却返回父窗口；旧 sheet 按钮索引可对应父窗口中的普通分类。必须在观察后由最新状态重新决定动作，不能在同一代码块中先刷新状态再无条件操作旧索引。可保存的截图必须取自同一次返回的 `StateAndScreenshot`，不能把随后的父窗口图命名为弹窗证据。日志确有 `intent=clear`，但该索引变化尚不足以解释确认词如何满足条件，不能归因为已证实的工具或系统缺陷。清除流程后续复现只用可丢弃临时库，不再触碰真实历史。
